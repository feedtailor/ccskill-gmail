## 概要

SKILL.md の「Gmail Search Queries」セクション（`newer_than` の例の近く）に、`newer_than` がスレッドの最終更新時刻を見るため、下書き編集や送信予約により意図しないヒットが発生しうる旨の注記を追加する。

## 背景

2026-04-25 の loop 運用セッションで、loop 巡回中のメール検索 (`newer_than:1h`) に「ユーザーが既に下書きを書き、送信予約済み」のスレッドが2件ヒットし、エージェントが「新着メール」と誤認して AskUserQuestion を発してしまう事象が発生。

調査の結果、以下が分かった:

- Gmail の `newer_than` は **スレッドの last activity time** を見ており、メッセージの受信時刻ではない
- そのため次の操作でスレッドが「new」扱いされる:
  - 新着受信（意図通り）
  - **下書きの追加・編集**（意図外）
  - **送信予約メッセージの存在**（さらに厄介で、未来日付でヒットする）
- 今回のケースは送信予約による未来日ヒット（date: `2026-04-27T00:05:00Z` = 2日後）だった

SKILL.md には `is:unread` の落とし穴と `lastSentMessage` / `hasDraft` の使い方は十分カバーされているが、いずれも「**返信が必要なメール**」の文脈で書かれており、「**`newer_than` で時間範囲を絞るときの落とし穴**」という別文脈は触れられていない。素朴に `newer_than:1h` を使ったエージェントが踏みやすい地雷になっている。

## 実装内容

SKILL.md の以下の位置に短い注記を追加する。

### 追加位置

`## Gmail Search Queries` セクション内、`is:unread` 注記（既存）の直下、または `newer_than` の例（`after:2024/01/01` などの近く）の直下。

### 追加文言（案）

```markdown
> **Note**: `newer_than` matches on thread last-activity time, not the original
> receipt time. Draft edits and scheduled-send messages bump it (scheduled sends
> can even produce future-dated hits). When you need "true new arrivals only",
> verify each result via `get_thread` and check `lastSentMessage.date` and
> `hasDraft`.
```

または日本語版が必要なら同等内容で。
