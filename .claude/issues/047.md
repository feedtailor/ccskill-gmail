## 概要

`ccskill-save-pdf` 関数内の `mktemp` テンプレートが macOS で正しく展開されず、一時ファイル名がリテラル `ccskill-pdf.XXXXXX.html` のまま生成される。これにより PDF 変換が失敗する。

## 再現手順

```bash
source .ccskill-gmail/api.sh && ccskill-save-pdf "$GMAIL_ENDPOINT" MESSAGE_ID ./out/test.pdf
```

**期待**: PDF が生成される
**実際**: exit code 1。HTML 保存の結果が2回出力され、PDF は生成されない

## 原因

`api.sh` 266行目:

```bash
tmphtml=$(mktemp "${TMPDIR:-/tmp}/ccskill-pdf.XXXXXX.html")
```

macOS の `mktemp` は **テンプレート末尾** の連続する `X` のみをランダム文字に置換する。`XXXXXX.html` のように `X` の後にサフィックスがあると、`X` は展開されずリテラルのまま残る。

```bash
# macOS での実際の挙動
$ mktemp "${TMPDIR}/ccskill-pdf.XXXXXX.html"
/var/folders/.../ccskill-pdf.XXXXXX.html    # X が展開されない！

$ mktemp "${TMPDIR}/ccskill-pdf.XXXXXX"
/var/folders/.../ccskill-pdf.a3Kf9m          # 正しく展開される
```

### 影響

1. **PDF 変換が常に失敗する**: Chrome headless に渡す一時ファイルパスが不正（原因の詳細は後述）
2. **同時実行時の競合**: 全呼び出しが同一ファイル名を使うため、並列実行でデータ破壊の可能性

### Chrome headless が失敗する理由（推定）

一時ファイル自体は作成され HTML も正しく書き込まれるが、Chrome headless の `--print-to-pdf` がこのファイルの変換に失敗している。`2>/dev/null` で stderr が抑制されているため正確なエラーは不明。直接 Chrome headless を同じ HTML ファイル（別パスにコピーしたもの）に対して実行すると成功するため、ファイル名やパス内の特殊文字が影響している可能性がある。

## 改修方針

### 方法: mktemp + mv でサフィックスを付与

```bash
tmphtml=$(mktemp "${TMPDIR:-/tmp}/ccskill-pdf.XXXXXX")
mv "$tmphtml" "${tmphtml}.html"
tmphtml="${tmphtml}.html"
```

macOS / Linux 両方で動作する安全なパターン。GNU coreutils の `mktemp --suffix=.html` は macOS 標準の `mktemp` では使えないため、`mv` 方式が最もポータブル。

### 修正箇所

- `api.sh` 266行目（`ccskill-save-pdf` 内の `mktemp` 呼び出し）

### 副次的改善（任意）

- Chrome headless 実行時の `2>/dev/null` を `2>&1` に変更し、失敗時のエラーメッセージを JSON レスポンスに含めるようにすると、今後のデバッグが容易になる
- 同様のパターンが他の関数にないか確認（`ccskill-download` 174行目、`ccskill-save-html` 221行目は `.html` サフィックスなしなので問題ない）
