## 概要

POST リクエスト用の JSON ペイロードを Write ツールで作成する際、現在は `/tmp/payload.json` のような OS の一時ディレクトリを使用しているが、Claude Code の Write ツールが内部的にパスを相対パスに変換する挙動があり、`Write(/tmp/*)` のパーミッションパターンにマッチしなくなってユーザに確認プロンプトが表示される問題がある。

一時ファイルの保存先を `.ccskill-gmail/tmp/` に変更し、この問題を解消する。

## 背景

### 現象

SKILL.md では `/tmp/payload.json` のように絶対パスで指定するよう指示しているが、Claude Code の Write ツールが出力時にパスを作業ディレクトリからの相対パス（例: `../../../../tmp/payload.json`）に変換して表示・パーミッション照合する。その結果、事前に設定した `Write(/tmp/*)` のパーミッションパターンにマッチせず、毎回ユーザに確認プロンプトが表示されて作業が中断する。

### なぜ /tmp/ ではダメか

- Claude Code のパス解決の挙動に依存しており、SKILL.md の指示だけでは制御できない
- ccskill-gmail は OSS として広く公開予定のため、特定環境のパス解決挙動に依存する設計は不適切
- 相対パスパターン（`Write(../../../../tmp/*)`）を使う回避策はナンセンス

### なぜファイル書き出しが必要か

POST リクエストの JSON にはメール本文等の長文テキストが含まれるケースが多く、インラインJSON（`api post '{...}'`）では実用的でない。stdin 対応は API 側の改修が必要でスコープが大きくなるため、ファイル経由のアプローチを維持する。

## 変更内容

### 1. `.ccskill-gmail/tmp/` ディレクトリの導入

- インストール時（`ccskill-gmail install`）に `.ccskill-gmail/tmp/` を作成
- `.ccskill-gmail/.gitignore` に `tmp/` を追加（事故コミット防止）

### 2. 一時ファイルの後片付け

API 呼び出し成功後に一時ファイルを削除する処理を入れる。方針:

- `api post @file` の実行後、API スクリプト側で使用済みの JSON ファイルを自動削除する
- または SKILL.md で「API 呼び出し後に一時ファイルを削除すること」を指示する

どちらが適切かは実装時に判断。API スクリプト側で自動削除する方がユーザ（AI）の負担が少なく確実。

### 3. SKILL.md / examples.md の更新

- `/tmp/payload.json` → `.ccskill-gmail/tmp/payload.json` に全箇所を変更
- パーミッション設定の説明も更新（`Write(.ccskill-gmail/tmp/*)`）

## 検証方法

1. `.ccskill-gmail/tmp/` に JSON を Write → `api post @.ccskill-gmail/tmp/payload.json` が確認プロンプトなしで通ること
2. API 呼び出し後に一時ファイルが削除されていること
3. `.ccskill-gmail/tmp/` が git 管理対象外であること
