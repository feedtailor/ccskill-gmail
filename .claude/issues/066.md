## 概要

GET リクエストで未知のアクションを指定した際のエラーレスポンスに、POST アクションの存在を示す情報を追加する。現状の hint は GET アクションのみを列挙するため、POST でしか使えないアクション（`mark_read` 等）が「存在しない」と誤認される。

## 背景

### 発生した事象

ftgmail プロジェクトで COTEN 領収書のワークフロー処理後、メールを既読にするため `mark_read` を呼び出した。その際、誤って GET メソッドで呼び出してしまった:

```bash
# 実行したコマンド（誤り）
.ccskill-gmail/api get action=mark_read messageId=19d2e3d4c07d8819
```

返されたエラーレスポンス:

```json
{
  "ok": false,
  "error": "Unknown action: mark_read",
  "error_code": "UNKNOWN_ACTION",
  "hint": "action パラメータを確認してください。利用可能: search, get_thread, get_message, list_labels, get_unread_count, list_attachments, get_attachment, get_message_html, list_drafts, get_profile"
}
```

### 問題の本質

エラーの hint が「利用可能:」として GET アクションだけを列挙している。この表現は **全アクションの完全な一覧** に見えるため、Claude（AI エージェント）がこれを信頼し「`mark_read` は存在しない機能」と誤判断した。

本来は SKILL.md を確認すれば POST アクションとして `mark_read` が存在することがわかるが、hint が「答え」を提示しているように見えたため、ドキュメントへの遡及確認が行われなかった。

### 正しいコマンド

```bash
# mark_read は POST（書き込み系）アクション
.ccskill-gmail/api post '{"action":"mark_read","threadId":"19d2e3d4c07d8819"}'
```

### 影響を受けるアクション

GET で誤って呼ばれうる POST アクションは以下の通り:

| アクション | 用途 |
|-----------|------|
| mark_read | 既読にする |
| mark_unread | 未読にする |
| archive | アーカイブ |
| add_label | ラベル追加 |
| remove_label | ラベル削除 |
| create_draft | 下書き作成 |
| create_reply_draft | 返信下書き作成 |
| update_draft | 下書き更新 |
| delete_draft | 下書き削除 |
| move_to_trash | ゴミ箱に移動 |

特に `mark_read`、`archive`、`add_label` は GET の読み取り操作に続けて呼ばれることが多く、メソッドを間違えやすい。

## 提案

GAS 側の `Unknown action` エラーレスポンスで、POST アクションの存在を示す情報を追加する。

### 案 A: hint に POST アクションも列挙する

```json
{
  "ok": false,
  "error": "Unknown action: mark_read",
  "error_code": "UNKNOWN_ACTION",
  "hint": "action パラメータを確認してください。GET で利用可能: search, get_thread, get_message, ... / POST で利用可能: create_draft, mark_read, mark_unread, archive, add_label, ..."
}
```

### 案 B: POST アクションを GET で呼んだ場合に専用メッセージを返す

POST アクション名のリストを保持し、GET で呼ばれた場合に特化したエラーを返す:

```json
{
  "ok": false,
  "error": "mark_read は POST メソッドで呼び出してください",
  "error_code": "WRONG_METHOD",
  "hint": "使い方: .ccskill-gmail/api post '{\"action\":\"mark_read\",\"threadId\":\"THREAD_ID\"}'"
}
```

### 推奨

**案 B を推奨。** 理由:

1. エラー原因が「アクションが存在しない」ではなく「メソッドが違う」であることが即座にわかる
2. 正しい使い方の例が提示されるため、SKILL.md を参照せずとも自己解決できる
3. AI エージェントが「機能が存在しない」と誤判断するリスクを根本的に排除できる

## 実装の検討

- GAS の `doGet` 関数内で、受け取った action が POST アクション一覧に含まれるかチェックする分岐を追加
- POST アクション名の一覧は `doPost` 側と共有する（定数化またはヘルパー関数）
- `api` シェルスクリプト側での対応も検討可能だが、GAS 側で対応する方がエラーメッセージの一貫性を保てる

## 備考

- 逆パターン（POST で GET アクションを呼んだ場合）にも同様の改善を適用すると、さらに堅牢になる
- この改善は AI エージェント利用時の信頼性向上に直結するが、人間の利用者にとっても有益
