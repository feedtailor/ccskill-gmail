## 概要

`ccskill-gmail install` 実行時に、`Bash(.ccskill-gmail/api *)` に加えて `Write(/tmp/*)` のパーミッションも `.claude/settings.local.json` に追加するか確認する。

## 背景

### 発生した問題

利用者が ccskill-gmail を使って POST リクエスト用の JSON ペイロードを作成する際、SKILL.md の指示に従い Write ツールで `/tmp/` にファイルを書き出す。しかし `Write(/tmp/*)` が `settings.local.json` の `permissions.allow` に含まれていないため、**毎回確認プロンプトが表示される**。

利用者はこれに気づかず「なぜ Bash は自動許可されるのに Write は毎回聞かれるのか？」と混乱する。

### 原因

- SKILL.md の frontmatter では `allowed-tools: Bash, Write` と宣言しており、スキルが Write ツールを使うことは明示されている
- しかし `lib/permissions.sh` の patterns 配列には `Bash(.ccskill-gmail/api *)` しか含まれていない
- Write ツールの許可パターンが漏れている

```bash
# lib/permissions.sh:23 (現状)
local patterns=("Bash(.ccskill-gmail/api *)")
```

### スキルでの Write ツール使用箇所

SKILL.md で Write ツールの使用を指示している箇所:

1. **POST 用 JSON の作成方法** — `cat` heredoc が禁止されており、Write ツールで `/tmp/payload.json` を作成してから `api post @/tmp/payload.json` で送信するパターンが正規手順として記載されている
2. **クロスシート参照（`!` を含む数式）の送信** — シェルの履歴展開回避のためファイル経由が必須

つまり Write ツールはスキルの基本的な書き込み操作に不可欠であり、Bash と同等に許可設定すべき。

## 提案

`lib/permissions.sh` の patterns 配列に `Write(/tmp/*)` を追加する。

```bash
# 修正後
local patterns=(
    "Bash(.ccskill-gmail/api *)"
    "Write(/tmp/*)"
)
```

これにより `ccskill-gmail install` 実行時の確認メッセージが以下のように変わる:

```
Claude Code の許可設定に以下のパターンを追加できます：
  - Bash(.ccskill-gmail/api *)
  - Write(/tmp/*)

これにより、Skill 使用時の確認プロンプトが軽減されます。
```

### 既存ユーザーへの影響

- 既にインストール済みのユーザーは `ccskill-gmail update` 時に `setup_permissions` が再実行されるため、差分パターン（`Write(/tmp/*)`）の追加が提案される
- 既存の `Bash(.ccskill-gmail/api *)` は「already configured」としてスキップされ、`Write(/tmp/*)` のみ追加確認される

## 備考

- ccskill-spreadsheet にも同様の問題がある可能性がある（同じ Write + `@file` パターンを使用）。横展開の検討を推奨
- `/tmp/` 以外のパスへの Write は引き続き確認が求められるため、セキュリティ上の懸念は小さい
