## 概要

メール内容を PDF として保存する際、SKILL.md の現状記述では `download`（添付ファイル取得）と `save-pdf`（本文 HTML → PDF 変換）が**同列のコマンドとして並んでいるだけ**で、両者の**使い分けの優先順位が示されていない**。

このため LLM はメールに公式の添付 PDF があるケースでも、本文を HTML 経由で PDF 化する `save-pdf` を先に呼んでしまいやすい。**領収書・請求書のように発行元が PDF を添付しているメールでは、添付PDF をそのまま保存すべき**であり、本文の HTML 変換を優先すべきではない。

SKILL.md に「PDF を保存する場合の取得元優先順位」を明示的なガイダンスとして追記し、LLM が常に添付 PDF を最優先で確認するように仕向ける。

## 背景 / 発生した事例

2026-05-11、ftgmail プロジェクトで Raycast Technologies からの月額領収書メールを処理した際、以下が起きた。

1. ユーザーから「Raycast の領収書を PDF 保存して」と依頼
2. アシスタント（Claude Code）は `save-pdf` を呼び、**メール本文の HTML を Chrome headless で変換した PDF** を保存
3. ユーザー指摘で `list_attachments` を実行したところ、メールには発行元が用意した正式 PDF が**2 件添付**されていた:
   - `Invoice-37AA3F80-387248.pdf` （請求書）
   - `Receipt-2982-6638.pdf` （領収書）
4. 本来は最初からこの添付 PDF を `download` サブコマンドで取得すべきだった

つまり「税務会計用の正式書類」として保存すべきだったのに、見栄えが崩れがちな**本文HTML変換版**が先に作成されてしまった。

## SKILL.md の現状記述（該当箇所）

### Command Templates セクション（およそ L241-L248）

```bash

.ccskill-gmail/api get action=list_attachments messageId=MESSAGE_ID
```

|--------|-------------|

### 問題点

- `download` と `save-pdf` の**使い分けの基準**が SKILL.md のどこにも書かれていない
- 「領収書 / 請求書のような公式 PDF 添付ケースをどう扱うか」というユースケース別の指針が無い
- `save-pdf` の説明は「HTML を取得して PDF 化する」とだけ書かれており、**添付PDFがあれば不要である**ことが伝わらない
- 結果として、LLM はメール本文を見るだけで PDF 化に進みやすく、`list_attachments` を先に呼ぶ習慣が付かない

## 改善提案

### 1. Command Templates の手前または直後に「Choosing between `download` and `save-pdf`」小節を追加

優先順位を明示する：

> When saving an email as a PDF, choose the source in this order:
>
> 1. **Attached PDF** — Always run `list_attachments` first. If the message has a `application/pdf` attachment, save that via the `download` subcommand. This is the publisher's authoritative document and must take precedence.
> 2. **PDF download URL inside the body** — Some services (Stripe, PayPal) include a "Download receipt/invoice" link in the email body. Fetch and rename that PDF rather than re-rendering the body.
> 3. **HTML body conversion (`save-pdf`)** — Last resort. Use only when no attached PDF and no in-body PDF link exist.
>
> Skipping step 1 will silently produce a worse artifact (re-rendered HTML) when an authoritative PDF was right there — common with receipts, invoices, statements.

### 2. `save-pdf` のコメントに警告を追記

```bash
# Save email as PDF (LAST RESORT — check list_attachments first;
#   if an attached PDF exists, prefer `download` over this command)
.ccskill-gmail/api save-pdf MESSAGE_ID ./email.pdf
```

### 3. `list_attachments` の説明を強調

「PDF 保存タスクに着手する前に必ず実行する」旨を一文添える。

### 4. SKILL.ja.md（日本語版）にも同様の修正を入れる

訳文は SKILL.md と意味的に同期させる。
