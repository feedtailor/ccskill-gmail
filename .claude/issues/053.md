## 概要

ccskill-gmail を複数 Google アカウントで同時運用できるようにする。clasp v3 の `--user <name>` 機能を活用し、`CLASP_USER` 環境変数で切り替える設計。

## 現状の問題

- `auth.sh` の `gas_token` が `tokens.default` をハードコード
- `push-gas.sh` の `clasp push/deploy` が `--user` を渡さない
- `install.sh` が `clasp login/create` にアカウント指定なし
- 複数アカウントの GAS Web App を同時運用できない

## 設計

### 核心: `CLASP_USER` 環境変数の導入

`.env` に `CLASP_USER` を追加し、全コンポーネントがこれを参照する。

```bash
# ~/projects/work/.env
GMAIL_ENDPOINT=https://script.google.com/.../exec
CLASP_USER=work

# ~/projects/personal/.env
GMAIL_ENDPOINT=https://script.google.com/.../exec
CLASP_USER=personal
```

未設定時は `default` にフォールバック（後方互換）。

### 変更ファイルと内容

#### 1. `lib/auth.sh` — `gas_token` のキー動的化

```bash
# Before
local RC_FILE="${CLASPRC_FILE:-$HOME/.clasprc.json}"
# ...
jq -r '.tokens.default.access_token // empty' "$RC_FILE"

# After
local RC_FILE="${CLASPRC_FILE:-$HOME/.clasprc.json}"
local USER_KEY="${CLASP_USER:-default}"
# ...
jq -r ".tokens.\"${USER_KEY}\".access_token // empty" "$RC_FILE"
```

`tokens.default` の全参照箇所（access_token, expiry_date, client_id, client_secret, refresh_token）とリフレッシュ時の書き込み箇所を `tokens.${USER_KEY}` に変更。

#### 2. `lib/push-gas.sh` — clasp コマンドに `--user` 渡し

```bash
# Before
(cd "$TMPDIR" && clasp push --force)
(cd "$TMPDIR" && clasp deploy ...)

# After
local CLASP_USER_OPT=""
if [ -n "${CLASP_USER:-}" ] && [ "$CLASP_USER" != "default" ]; then
    CLASP_USER_OPT="--user $CLASP_USER"
fi
(cd "$TMPDIR" && clasp $CLASP_USER_OPT push --force)
(cd "$TMPDIR" && clasp $CLASP_USER_OPT deploy ...)
```

#### 3. `commands/install.sh` — アカウント指定オプション追加

- `ccskill-gmail install --user work` のように `--user` オプションを受け付ける
- `clasp --user $USER login` / `clasp --user $USER create` に渡す
- `.env` 生成時に `CLASP_USER=$USER` を追記
- 未指定時は従来通り（`default`）

#### 4. `commands/update.sh` — `.env` から `CLASP_USER` を読み込み

- update 時は `.env` を source して `CLASP_USER` を取得
- `push_gas` / `deploy_gas` に渡す（`push-gas.sh` が参照）

#### 5. `.env` 生成テンプレートの変更

```bash
# Before
GMAIL_ENDPOINT=${ENDPOINT_URL}

# After
GMAIL_ENDPOINT=${ENDPOINT_URL}
CLASP_USER=${CLASP_USER_VALUE}   # --user 指定時のみ追記（default の場合は省略）
```

### 後方互換性

- `CLASP_USER` 未設定 → `default` にフォールバック → 既存環境は一切影響なし
- `CLASP_USER=default` と未設定は同じ動作
- `.env` に `CLASP_USER` がなくても動く

### データフロー

```
.env (CLASP_USER=work)
  ↓ source
api.sh / _ccskill_init()
  ↓ source auth.sh
gas_token()
  ↓ tokens.work を参照
curl -H "Authorization: Bearer ..."
  ↓
GAS Web App (Account B)
```

```
.env (CLASP_USER=work)
  ↓ source
push-gas.sh
  ↓ clasp --user work push
GAS プロジェクト (Account B)
```

### 既存プロジェクトの移行

専用コマンド（switch-account 等）は不要。既存ユーザーは `.env` に `CLASP_USER=<name>` を手動追記すれば切り替え可能。ドキュメントで案内する。

## ユーザーのオペレーション（マルチアカウント設定時）

```bash
# 1. 仕事用アカウントでログイン
clasp --user work login
# → ブラウザで Account A にログイン

# 2. 仕事用プロジェクトをインストール
ccskill-gmail install --user work work-gmail ~/projects/work

# 3. 個人用アカウントでログイン
clasp --user personal login
# → ブラウザで Account B にログイン

# 4. 個人用プロジェクトをインストール
ccskill-gmail install --user personal my-gmail ~/projects/personal

# 以降は cd するだけで自動切り替え
cd ~/projects/work
source .ccskill-gmail/api.sh && ccskill-get "$GMAIL_ENDPOINT" action=search query="is:unread"
# → Account A の Gmail

cd ~/projects/personal
source .ccskill-gmail/api.sh && ccskill-get "$GMAIL_ENDPOINT" action=search query="is:unread"
# → Account B の Gmail
```
