## 改善内容

### 1. `reference/triage.md` の Classification signals を更新

現状:
```markdown
- **waiting**: Last message in thread is from user, or thread has "I'll get back to you" pattern
```

改善後:
```markdown
- **waiting**: `lastSentMessage.from` is the user (i.e., the user sent the most recent **non-draft** message), or thread has "I'll get back to you" pattern. **Do NOT use `messages[-1]` for this judgment** — use `lastSentMessage`, which is computed server-side excluding drafts.
```

### 2. `reference/triage.md` 冒頭の警告ブロックに新フィールド使用ルールを追記

094 で追加された "When to use this document" セクションの直後に、以下のサブセクションを追加:

```markdown
### Always use `lastSentMessage` (NOT `messages[-1]`) to determine the last sender

`get_thread` returns drafts inline with sent messages. A freshly created reply draft will appear at the end of `messages[]` and can be misclassified as "sent reply" if you read `messages[-1]` directly.

The response includes two helper fields specifically for triage:

| Field | Type | Purpose |
|-------|------|---------|
| `lastSentMessage` | object \| null | The most recent **non-draft** message (full message object). Use this to determine "who spoke last". |
| `hasDraft` | bool | True if the thread contains at least one draft. Useful to detect "I already drafted a reply but haven't sent it yet". |

Always use these fields. Treat `messages[-1]` as untrusted for the "last sender" judgment.
```

### 3. `reference/triage.md` の Step 2 (Classify Each Thread) に判定例を追加

Classification signals の直前または直後に、典型的な判定パターンを追加:

```markdown
### Reading the response

```bash
.ccskill-gmail/api get action=get_thread threadId=THREAD_ID
```

Then read these top-level fields from `data`:

- `data.lastSentMessage.from` — who sent the last non-draft message
- `data.lastSentMessage.date` — when
- `data.hasDraft` — whether a draft is present in the thread

If `data.lastSentMessage.from` matches the user → likely **waiting**.
If `data.lastSentMessage.from` is someone else → likely **reply-now** or **draft-needed**.
If `data.hasDraft` is `true` → check whether the existing draft is yours and ready to send (do NOT create another draft on top).
```

### 4. `SKILL.md` の Email Review Guidelines に追記

### ⚠️ Use `lastSentMessage` (NOT `messages[-1]`) when checking the last sender

`get_thread` returns drafts inline with sent messages. A reply draft you just created will appear at the end of `messages[]` and look like a sent reply.

The response provides two helper fields specifically for triage:

- `lastSentMessage` (object | null) — the most recent **non-draft** message

Always use `lastSentMessage` for the "who spoke last" judgment. Treat `messages[-1]` as unreliable.

See [reference/triage.md](reference/triage.md) for the full triage workflow.
```
