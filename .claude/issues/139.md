## 概要

現在のインストールは「入手 → `setup` → `account add` → `skill install`」の 4 手で、ステップが多い。`setup` が `skill install` と `account add` まで実行するようにし、利用者の手順を「入手 → `setup`」で完結させる。初心者にも優しい一発完結を狙う。

## 現状（コード根拠）

- `setup`（`commands/setup.sh`）は clasp ローカル導入 ＋ `~/.local/bin` への symlink ＋ PATH 確認までで終わり、末尾で `account add` / `skill install` を「次にこれを実行」と**案内するだけ**（`setup.sh:130-133`）。
- `account add` の認可フローは既に SSH/リダイレクトループ対策を内蔵: 認可 URL を標準出力に明示、「ブラウザが開かなければ手動で開く（SSH 環境）」、リダイレクトループ時の incognito 復旧手順、`read -p` での一拍待ち（`lib/provision.sh:149-168`）。よって `setup` から呼んでも新たな危険は増えない。

## 変更後の挙動

`setup` の最後に次の 2 つを順に実行する:

1. **`skill install`**（自動・非対話）。symlink を張るだけで冪等。`~/.claude/skills/` に既登録なら既存処理がそのまま検知する。
2. **`account add`**（自動・[Y/n] で尋ねない）。ブラウザ認可は既存フローのまま（Enter で認可ページを開く・URL を出力・失敗時の手順案内）。

順序は「clasp + PATH → `skill install` → `account add`」とし、**失敗しやすい対話の `account add` を最後**に置く。`account add` が失敗・中断しても手前のステップは完了済みなので、`setup` 自体は致命終了させず「`ccskill-gmail account add` を後で再実行してください」と案内して終える。

### 冪等性（再実行時の配慮）

- `skill install`: 既存の symlink 判定で二重登録にならない（現状どおり）。
- `account add`: 既に 1 件以上登録済み（`accounts_count > 0`）なら**自動実行しない**。「登録済みのため account add はスキップ。アカウントを追加するには ccskill-gmail account add」を案内するに留める。これにより `setup` を再実行しても認可フローが毎回走らない。

## 呼び出し方法（実装メモ）

- `setup` 初回は `~/.local/bin` がまだ PATH に無い場合があるため、`skill install` / `account add` は PATH 経由ではなくディスパッチャ実体（`$CCSKILL_GMAIL_DIR/ccskill-gmail account add` 等）で呼ぶ。
- `setup.sh` は `set -e`。`account add` の戻り値で `setup` を落とさないよう、その呼び出しだけ失敗許容（`|| true` 相当）にし、結果に応じて案内を出し分ける。
