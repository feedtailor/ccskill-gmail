## 概要

SKILL.md の POST 用 JSON 作成方法セクションに、`/tmp/` 以下への複数ファイルの並列 Write を避けるよう注意書きを追加する。

## 背景

Claude Code の Write ツールには「未 Read のファイルには書き込めない」という内部ガードがある。新規ファイル作成時でも、同一メッセージ内で複数の `/tmp/` ファイルを並列に Write すると、2つ目以降が「File has not been read yet」エラーで失敗することがある。

### 発生した事象（2026-04-01）

ccskill-spreadsheet と連携する bizmobile-task スキル実行中に、2つの案件のスプレッドシート更新用 JSON を並列作成しようとした：

```
# 同一メッセージ内で並列実行 → 2つ目が失敗
Write("/tmp/flyhight_update.json")   → 成功（新規作成）
Write("/tmp/kurashima_update.json")  → エラー: "File has not been read yet"
```

結果、ユーザーに確認プロンプトが表示され、ccskill シリーズの最重要原則「エージェント AI が止まらないこと」に反する状況が発生した。

ccskill-gmail でも POST 用 JSON を `/tmp/` に Write する同じパターンを採用しているため、複数の下書きを連続作成する場面（例: 顧客向けメールと Apple 向けメールの下書きを同時作成）で同様の問題が起きる可能性がある。

### 原因

Write ツールは呼び出し前にそのファイルパスの Read 履歴を確認する。並列呼び出しの場合、2つ目の Write が実行される時点で当該ファイルの Read 履歴が存在しないため、ガードに引っかかる。

## 対応内容

SKILL.md の `POST 用 JSON の作成方法` セクション（`important` ブロック内）に、以下の趣旨の注意書きを追加する：

```markdown
**複数ファイルの並列 Write 禁止:** `/tmp/` に複数の JSON ファイルを書き出す場合は、Write ツールを並列ではなく順次実行すること。並列に Write すると2つ目以降が「File has not been read yet」エラーで失敗し、確認プロンプトが発生する。Write は順次実行し、その後の Bash（API 呼び出し）は並列実行して構わない。
```
