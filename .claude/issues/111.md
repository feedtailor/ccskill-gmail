## 概要

`#100` で導入された master 側アップデートチェックが、`commands/info.sh` / `commands/doctor.sh` / `commands/status.sh` / `commands/install.sh` の 4 箇所で **fetch あり版** (`update_check_format_oneline`) を呼んでいるため、これらコマンドを実行するたびに `git -C $CCSKILL_GMAIL_DIR fetch --quiet origin main` が走る。

ディスパッチャ (`ccskill-gmail:58`) では既に **fetch なし版** (`update_check_format_oneline_cached`) を使ってバージョン行に "(up to date)" / "(N commits behind)" を表示しているため、各コマンド側で再度 fetch するのは二重実行で、UX を阻害する副作用しか生んでいない。

## 具体事象

ユーザーが `ccskill-gmail info` を実行したときの観測:

```
% ccskill-gmail info

ccskill-gmail info
================================================

  Account:       oishi@feedtailor.jp
  Directory:     ~/projects/ftgmail
  Version:       2aa0fdb (up to date)
  Installed:     2026-02-26 21:51:10
  Updated:       2026-05-09 10:28:51

  Permissions:
    Denied:      move_to_trash

  Inbox:         7475 unread
  Starred:       10 unread
Enter passphrase for key '/Users/oishi/.ssh/id_ed25519':
```

`Starred: 10 unread` まで描画された後、最後に **SSH 秘密鍵のパスフレーズプロンプトでブロック**されている。

## 影響を受ける環境

これは特定ユーザーだけの問題ではなく、ccskill-gmail を使うあらゆる環境で UX を悪化させる。

| 環境 | 起こること |
|---|---|
| パスフレーズ付き SSH 鍵 (`id_ed25519` 等) | 毎回プロンプトが出てブロック |
| ssh-agent の active セッション無し | 同上 |
| オフライン / ネットワーク不通 | `git fetch` のタイムアウトまで待たされる |
| 高 RTT / 遅い回線 | info が毎回数秒遅延 |
| 企業ファイアウォール経由 | github.com 制限環境ではハング |
| プライバシー意識の高いユーザー | info を打つたびに GitHub へ phone home が走ることに違和感 |

## 原因

`grep -rn 'update_check_format_oneline\|update_check_run\|_update_check_fetch' commands/ lib/ ccskill-gmail` の結果:

```
commands/info.sh:246    update_check_format_oneline ...   ← fetch あり
commands/install.sh:164 update_check_format_oneline ...   ← fetch あり
commands/doctor.sh:96   update_check_format_oneline ...   ← fetch あり
commands/status.sh:219  update_check_format_oneline ...   ← fetch あり
ccskill-gmail:58        update_check_format_oneline_cached ← fetch なし（正しい）
```

API 設計としては `update_check_format_oneline` (fetch あり) と `update_check_format_oneline_cached` (fetch なし) の 2 種が用意されているが、各コマンドが**前者を選択している**ことで毎回 fetch される。

`stderr` を `/dev/null` に捨てているが、SSH パスフレーズプロンプトは制御端末経由で出るため抑制できず、TTY をブロックする。

## 改善策

### 必須修正

`commands/info.sh:246`, `commands/install.sh:164`, `commands/doctor.sh:96`, `commands/status.sh:219` の 4 箇所を **`update_check_format_oneline_cached` に変更**する。

ディスパッチャ側で既にキャッシュベースの up-to-date 表示を行っているため、各コマンドの末尾で改めてアップデート通知を出す処理は冗長。キャッシュ版に切り替えても情報量は減らない。

### 副次対応（防御層）

`lib/update_check.sh:_update_check_fetch_and_count` 内の `git fetch` に `GIT_SSH_COMMAND='ssh -o BatchMode=yes -o ConnectTimeout=5'` を付与する。これにより、将来 fetch が呼ばれる経路で:

- パスフレーズ要求は無音失敗（プロンプトなし）
- 接続できないホストは 5 秒で諦める

の 2 点を保証できる。`update` 本体コマンド由来の明示的な fetch だけは BatchMode を外す（ユーザーが明示的に呼んでいるので対話を許可してよい）。

### fetch を実際に行うべき場所

- `ccskill-gmail update` 本体実行時（既にユーザーが pull→update を期待している文脈）
- もしくは新設する `ccskill-gmail update-check --refresh` のような明示コマンド

info/doctor/status/install は表示専用に振り切る。
