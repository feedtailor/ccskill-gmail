## タスク概要

`update_draft` で返信下書きの to/cc 等を変更すると、スレッドとの紐付けが失われるバグを修正する。

## 問題

### 再現手順

1. `create_reply_draft` でスレッドへの返信下書きを作成
2. `update_draft` で to や cc を変更
3. 下書きが元のスレッドから切り離され、孤立した新規メールになる

### 根本原因

`handleUpdateDraft` (gas-template/handlers/draft.js:100-134) の「削除して再作成」ロジック:

```javascript
// 現在の実装
draft.deleteDraft();
const newDraft = GmailApp.createDraft(currentTo, currentSubject, currentBody, options);
```

- `create_reply_draft` は `lastMessage.createDraftReply()` を使用し、`In-Reply-To` / `References` ヘッダが自動設定される
- `update_draft` は `GmailApp.createDraft()` で新規作成するため、これらのヘッダが失われる
- 結果としてスレッドの連続性が破壊される

## 修正方針

返信下書きかどうかを判定し、返信下書きの場合は `createDraftReply` で再作成する。

### 判定ロジック

下書きが属するスレッドに下書き以外のメッセージが存在する場合、返信下書きと判定する。

```javascript
const thread = message.getThread();
const threadMessages = thread.getMessages();
const isReplyDraft = threadMessages.length > 1
  || (threadMessages.length === 1 && !threadMessages[0].isDraft());
```

### 修正後のフロー

```
update_draft 呼び出し
  ↓
既存下書きのスレッド情報を取得
  ↓
返信下書きか判定
  ├─ YES → draft.deleteDraft()
  │        → 下書き以外の最後のメッセージに対して createDraftReply(body, options)
  │          （options.to で宛先変更対応）
  └─ NO  → draft.deleteDraft()
           → GmailApp.createDraft(to, subject, body, options)（従来通り）
```

## 実装箇所

### gas-template/handlers/draft.js

`handleUpdateDraft` 関数を以下のように修正:

```javascript
function handleUpdateDraft(draftId, to, subject, body, cc, bcc) {
  requireParam(draftId, 'draftId');

  const drafts = GmailApp.getDrafts();
  const draft = drafts.find(function(d) { return d.getId() === draftId; });
  if (!draft) {
    return errorResponse(`Draft not found: ${draftId}`);
  }

  const message = draft.getMessage();
  const currentTo = to || message.getTo();
  const currentSubject = subject || message.getSubject();
  const currentBody = body || message.getPlainBody();

  // スレッドに紐付いているか判定
  const thread = message.getThread();
  const threadMessages = thread.getMessages();
  const isReplyDraft = threadMessages.length > 1
    || (threadMessages.length === 1 && !threadMessages[0].isDraft());

  const options = buildEmailOptions({ cc: cc, bcc: bcc });

  draft.deleteDraft();

  let newDraft;
  if (isReplyDraft) {
    // 返信下書き → スレッドの最後の非下書きメッセージに対して再作成
    const nonDraftMessages = threadMessages.filter(function(m) {
      return !m.isDraft();
    });
    const replyTarget = nonDraftMessages[nonDraftMessages.length - 1];

    if (to) options.to = to;
    newDraft = replyTarget.createDraftReply(currentBody, options);
  } else {
    // 新規下書き → 従来通り
    newDraft = GmailApp.createDraft(currentTo, currentSubject, currentBody, options);
  }

  return successResponse({
    draftId: newDraft.getId(),
    oldDraftId: draftId,
    threadId: thread.getId(),
    isReply: isReplyDraft,
    action: 'update_draft',
    message: '下書きを更新しました',
    gmailUrl: 'https://mail.google.com/mail/u/0/#drafts'
  });
}
```

### 変更のポイント

| 観点 | 説明 |
|------|------|
| スレッド維持 | `createDraftReply` で再作成するため `In-Reply-To` / `References` が維持される |
| to 変更対応 | `createDraftReply` の options.to で宛先を上書き可能 |
| cc/bcc 変更対応 | options.cc / options.bcc で変更可能 |
| 判定ロジック | スレッド内に下書き以外のメッセージがあれば「返信」と判断 |
| 後方互換 | 新規下書きの update は従来通りの動作 |
| レスポンス拡張 | `threadId` と `isReply` を追加で返す |
