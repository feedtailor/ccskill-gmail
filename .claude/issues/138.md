## 概要

`ccskill-gmail account add` で 2 個目以降のアカウントを登録するとき、別名（ラベル）を `--label` フラグで**認証前に**指定させている。だが、どの Google アカウントを選ぶかはブラウザ認証で初めて確定するため、「認証前にラベルを考えて打つ」導線は不自然で、ラベルを付け忘れるとフルメールアドレスでしか指名できなくなる。ラベルの指定を**認証後の対話**に移し、`--label` は任意のショートカットとして残す。

## 現状の挙動（コード根拠）

- `--label` なしで `account add` しても失敗はしない。内部の clasp ユーザー名 `ccskill-acct-main` が既にあれば `ccskill-acct-main-2` へ自動採番し（`commands/account.sh:102-108`）、新規ログインが走って 2 個目として登録される。
- ただし**ラベルが空のまま**になり、そのアカウントは `accounts.json` のキー（フルメールアドレス）でしか指名できない（`accounts_get` はメール or ラベルで解決、`lib/accounts.sh:169-191`）。
- ラベルは内部の clasp ユーザー名とは独立した `accounts.json` のフィールド（`accounts_upsert ... "$LABEL"`、`commands/account.sh:165` / `lib/accounts.sh:143-153`）。よって clasp ログイン用の内部名は機械採番のまま、人が見るラベルだけ認証後に決められる。
- メールアドレスは認証後に GAS の `get_profile` で自動確定する（`commands/account.sh:149-162`）。ユーザーがメールを手入力する箇所はない。

## 変更後の挙動

1. `account add`（`--label` なし）→ ブラウザ認証 → メールアドレス確定（ここまで現状どおり）。
2. **1 個目**: そのまま default として登録。ラベルは尋ねない（default かメールで指名できる）。
3. **2 個目以降**（既に登録が 1 件以上ある）: メールアドレスを提示し、対話でラベルを尋ねる。

   ```
   このアカウント (foo@gmail.com) を呼び出すラベルを入力してください (省略可・例: work, personal): 
   ```

   - 入力値をラベルとして紐づける。空入力はラベルなし（従来どおりメールで指名）。
   - 英数字・ハイフン・アンダースコア以外、または既存ラベルとの重複は、その場で再入力を促す。
4. `--label` を明示した場合は従来どおり対話を出さない（非対話・スクリプト用に残す）。
5. 対話できない環境（非 TTY: 自動実行・sandbox 等）では対話を出さず、空ラベルで登録（従来の縮退挙動を維持）。
6. 既に登録済みのメールアドレスを再 `add` した場合は対話を出さず、既存ラベルを維持する。

内部の clasp ユーザー名（`ccskill-acct-main-N`）はラベルと一致しないが、これは内部識別子であり利用者には見えない。意図的に分離する。

## テスト（TDD）

`tests/lib/` にユニットテストを追加する（既存の bash テストフレームワーク `test-helper.sh` を使用）。

- `accounts_validate_label`: 空＝OK / `work`＝OK / `info-ft`＝OK / `a b`＝NG / `日本語`＝NG / `a@b`＝NG
- `accounts_label_exists`: fixture の `accounts.json` に対し、既存ラベルで真・未使用ラベルで偽
- `accounts_prompt_label`: stdin を流し込み、(1) 一発で有効な値→その値 (2) 無効→再入力→有効値 (3) 重複→再入力→有効値 (4) 空入力→空 を確認

`cmd_add` 全体は実際の clasp/GAS を伴うため自動テスト対象外。対話ロジックを `accounts_prompt_label` に切り出して単体検証する。
