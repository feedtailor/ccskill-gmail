## 概要

`commands/update.sh` のスキル定義同期ロジックが `find | basename | cp` でファイルを宛先トップレベルにフラット化している。`reference/triage.md` のようなサブディレクトリ配下のファイルが宛先では `triage.md`（トップレベル）になってしまう。

`commands/install.sh` 側は `cp -r` でディレクトリ構造を保持しており、**install と update で挙動が非対称**。これは長年潜在していたバグ。

## 該当箇所

`commands/update.sh:177-191`

```bash
echo "Step 1: Updating skill definition..."

# ソースとターゲットが同一ディレクトリの場合はスキップ
SRC_SKILL_DIR=$(cd "$CCSKILL_GMAIL_DIR/.claude/skills/ccskill-gmail" 2>/dev/null && pwd)
DST_SKILL_DIR=$(cd "$SKILL_DIR" 2>/dev/null && pwd)

if [ "$SRC_SKILL_DIR" = "$DST_SKILL_DIR" ]; then
    echo -e "${YELLOW}Skipping skill definition copy (source and target are the same)${NC}"
else
    # メタデータ以外をコピー
    find "$CCSKILL_GMAIL_DIR/.claude/skills/ccskill-gmail" -type f ! -name '.ccskill-metadata.json' | while read file; do
        filename=$(basename "$file")                      # ← ディレクトリ情報を捨てている
        cp "$file" "$SKILL_DIR/$filename"                 # ← トップレベルに平坦化
    done
fi
```

## 影響

### 既存ユーザーが update を実行した場合

1. `reference/` 配下のファイルが宛先トップレベルにフラット化される
2. install 時に作られた古い `reference/` ディレクトリが残ったまま、新ファイルが反映されない
3. SKILL.md が `[reference/triage.md](reference/triage.md)` のような相対リンクで `reference/` 配下を指している場合、リンク先の実体がトップレベルにあるため **リンク切れになる**

### 094/095 への直接影響

#094 で SKILL.md から `reference/triage.md` への導線を追加したが、既存ユーザーが update を実行すると即座にこのリンクが壊れる。Claude が triage.md にたどり着けず、`is:unread` 偏重の旧パターンに戻る恐れがある。**094/095 の効果を打ち消す**ため、本 issue は #094 の前提条件として扱うべき。

## 改善内容

### 案A: `cp -r` でディレクトリ構造を保持（install.sh と揃える）

```bash
if [ "$SRC_SKILL_DIR" = "$DST_SKILL_DIR" ]; then
    echo -e "${YELLOW}Skipping skill definition copy (source and target are the same)${NC}"
else
    # メタデータ以外をコピー（ディレクトリ構造を保持）
    cp -r "$CCSKILL_GMAIL_DIR/.claude/skills/ccskill-gmail/"* "$SKILL_DIR/"
    # メタデータファイルが存在すれば消す（コピー後の念のため）
    rm -f "$SKILL_DIR/.ccskill-metadata.json"
fi
```

注意点:
- 既存ファイルの上書きが必要なので `cp -r` は POSIX 的に大丈夫（macOS / Linux 両方で動く）
- メタデータ除外を find で行う場合は `find ... ! -name '.ccskill-metadata.json' -print0 | xargs -0` 等の工夫が必要
- 古いインストールに残った stale な top-level ファイル（例: 古い triage.md）は別途クリーンアップが必要かも

### 案B: 相対パスを保持する find ベースの実装

```bash
if [ "$SRC_SKILL_DIR" = "$DST_SKILL_DIR" ]; then
    echo -e "${YELLOW}Skipping skill definition copy (source and target are the same)${NC}"
else
    pushd "$CCSKILL_GMAIL_DIR/.claude/skills/ccskill-gmail" > /dev/null
    find . -type f ! -name '.ccskill-metadata.json' | while read file; do
        rel="${file#./}"
        mkdir -p "$SKILL_DIR/$(dirname "$rel")"
        cp "$file" "$SKILL_DIR/$rel"
    done
    popd > /dev/null
fi
```

案A の方がシンプル。案B はファイル単位の制御が必要な場合の選択肢。

### 既存ユーザー対応

過去にフラット化された stale なファイルが宛先に残っている可能性がある。update.sh の冒頭で以下のクリーンアップを検討:

```bash
# 過去のフラット化バグで残った stale なファイルを削除
# （reference/ にも同名ファイルが存在し、トップレベルが古い場合のみ）
for f in triage.md commitment.md search.md thread.md label.md draft.md status.md read.md index.md; do
    if [ -f "$SKILL_DIR/$f" ] && [ -f "$SKILL_DIR/reference/$f" ]; then
        rm "$SKILL_DIR/$f"
    fi
done
```

ただしこのクリーンアップは破壊的なので、`--force` フラグ付きの場合のみ実行する等の慎重さが必要。
