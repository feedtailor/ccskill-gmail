## 概要

レシピ仕組みの基盤ディレクトリ構造と README を整備し、最初の 3 本のレシピを実装する。これが完了すれば LP に「Recipes」訴求を出せる状態になる。

## 背景

#102 の構想に基づく Phase 0-1。設計方針・ディレクトリ構造の詳細は #102 参照。

## 実装内容

### 1. 基盤構築

- `.claude/skills/ccskill-gmail/recipes/` ディレクトリ作成
- `recipes/README.md` — レシピの概念、一覧、実行方法、追加方法を記述
- `SKILL.md` に recipes への導線を末尾に 1 段落追加 (progressive context injection を意識し浅く)

### 2. 最初のレシピ 3 本

各レシピは以下を含む:
- `README.md` — Pain、前提、期待結果
- `prompt.md` — Claude に渡す定型プロンプト
- `example-output.md` — サンプル出力
- 必要に応じて `config-sample.js` / `automation.sh`

**R1: weekly-exec-digest**
- 目的: 先週の `is:important OR is:starred` スレッドを要約し Markdown 出力
- action: `search`, `get_thread`
- 出力: 差出人・件名・状況・要アクションを表形式でまとめた .md
- 対応 Pain: LP Pain 03 (週次レポート)

**R2: invoice-pdf-bundle**
- 目的: 指定期間の請求書・領収書 PDF を規則ファイル名で一括保存
- action: `search has:attachment`, `get_thread`, `list_attachments`, `get_attachment`
- 付属: `automation.sh` (ファイル名整形)
- 出力: 指定ディレクトリに `YYYYMMDD_取引先_金額_種別.pdf` 形式で保存

**R3: daily-briefing**
- 目的: 昨日夕方以降 〜 今朝までの重要メールを 3 行要約
- action: `search newer_than:1d`, `get_thread`
- 出力: 朝イチで読める短いサマリー
- 対応 Pain: LP Pain 01 (朝イチ未読)

### 3. SKILL.md 導線の記述

recipes の存在と使い方を AI が認識できる最小の一文を末尾に追加。例:

```
## Recipes

このスキルには、特定業務向けに型化された「レシピ」が付属している。
ユーザーがレシピ名を呼び出した場合、`recipes/<name>/prompt.md` を参照して実行する。
利用可能なレシピの一覧と概要は `recipes/README.md` を参照。
```
