## 概要

`ccskill-gmail update` を実行したとき、対象範囲のコミットに `feat:` / `fix:` が**1件もない**場合に、変更件数表示が 2 系統で壊れる。

```
Changes (0
0):
--------
  (Unable to show changes)
```

問題は 2 つあり、原因は同根（grep の exit code を「失敗」と誤解釈している）:

1. `Changes ($N):` の `$N` 部分に `0` が改行を挟んで2つ表示される
2. 件数が 0 のときに `(Unable to show changes)` が出る — これは **git が失敗したかのように見える誤メッセージ**で、実際は単に feat/fix が無いだけ

## 再現条件

`docs:` / `chore:` / `test:` / `refactor:` だけのコミットを範囲に含む update。例えば本 issue を提起したきっかけは:

```
$ ccskill-gmail update
Current version: e8a02ca
Latest version:  bd8bbe4

Changes (0
0):
```

`e8a02ca..bd8bbe4` の差分は `docs: issue #111 を完了に更新` の 1 コミットのみで、これは feat/fix どちらでもないので集計対象 0 件。

## 原因

### 問題 1: `Changes (0\n0):`（commands/update.sh:149）

```bash
TOTAL_COMMITS=$(cd "$CCSKILL_GMAIL_DIR" && git --no-pager log --no-merges --format="%s" "${CURRENT_VERSION}..${GLOBAL_VERSION}" 2>/dev/null | grep -cE "^(feat|fix):" || echo "0")
```

挙動の分解:

- `grep -c` はマッチ 0 件のとき**標準出力に `0` を吐き、exit 1 を返す**
- `|| echo "0"` が exit 1 を見て**追加で `0` を出力**
- 結果 `TOTAL_COMMITS` が `"0\n0"`（2 行）になる
- `echo "Changes ($TOTAL_COMMITS):"` がそのまま展開され `Changes (0\n0):` と見える

### 問題 2: `(Unable to show changes)`（commands/update.sh:152）

```bash
(cd "$CCSKILL_GMAIL_DIR" && git --no-pager log --no-merges --format="  %cd  %s" --date=short "${CURRENT_VERSION}..${GLOBAL_VERSION}" 2>/dev/null | grep -E "^  [0-9]{4}-[0-9]{2}-[0-9]{2}  (feat|fix):") || echo "  (Unable to show changes)"
```

- `grep -E` は **マッチ 0 件で exit 1**（GNU grep 仕様）。
- `||` がこれを「コマンドが失敗した」と解釈し、`Unable to show changes` を出す。
- しかし実際にはコマンドは成功しており、単に**ユーザー向け変更（feat/fix）が無いだけ**。
- このため、docs/chore/test だけの差分の update でも「git が失敗したかのように」見える。

両方とも、grep の exit 1 を「失敗」と扱っている同根のミス。

## 改善策

### 問題 1 の修正

```bash
TOTAL_COMMITS=$(... | grep -cE "^(feat|fix):" || true)
```

`grep -c` は既にマッチ 0 件でも `0` を出力するので、`||` 側で改めて値を出力する必要は無い。exit code を握り潰すだけで十分。

### 問題 2 の修正

`TOTAL_COMMITS` の値で分岐させ、エラー扱い（`Unable to show changes`）と「変更なし」を区別する:

```bash
if [ "$TOTAL_COMMITS" -eq 0 ]; then
    echo "  (no user-facing changes — docs/chore/test only)"
else
    (cd ... | grep -E ...) || echo "  (Unable to show changes)"
fi
```

- `0` 件 → ユーザーに見せる変更が無いだけなのでポジティブな表現
- `>0` 件で grep が失敗するのは git が壊れているなどの異常時のみ → そのときに限り `Unable to show changes` を出す（妥当）

### 代替案（採用しない）

- `wc -l | tr -d ' '` を使う方法もあるが、`grep -c` で完結している現状から余計な変更が増える
- 関数化（`count_user_facing_commits`）してから fix する案もあるが、1 行のバグ修正に対しては overspec
