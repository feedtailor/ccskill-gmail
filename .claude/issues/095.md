## 改善内容

### 1. `is:unread` anti-pattern を明示

Email Review Guidelines セクションに以下の警告ブロックを追加:

```markdown
### ⚠️ Do NOT filter by `is:unread`

**Unread ≠ unreplied.** A Gmail message becomes "read" the moment the user opens it in
any Gmail client (web, mobile app, preview pane) — but that does not mean they have
replied. In Japanese business email workflows especially, users routinely scan an email
to understand it, then leave it in the inbox to reply later.

When looking for emails that need a reply, **never include `is:unread`** in the query.
Instead:

- Use `in:inbox -from:me` to find threads where the last actor was not the user
- Fetch each thread and check whether the **last message** was sent by someone other
  than the user (this is the authoritative signal for "awaiting reply")
- Date range: `newer_than:7d` to `newer_than:14d` is a reasonable default; shorter
  windows (e.g., `newer_than:1d`) will miss stalled replies
```

### 2. 典型クエリを本文に1行だけでも記載

「examples.md §19 を見よ」という行末ポインタは視認性が低く、Claude が辿りにくい。本文に以下を追記:

```markdown
### Recommended query for "emails that need a reply"

\`\`\`bash
.ccskill-gmail/api get action=search query="in:inbox -from:me newer_than:7d -category:promotions -category:social -category:updates -category:forums" maxResults=30
\`\`\`

Then for each thread, call `get_thread` and check whether the last message's `from`
is not the user. If it is not, the thread is a reply-now / draft-needed candidate
(see [triage.md](triage.md) for full classification).
```

### 3. セクション位置の昇格

現在の Email Review Guidelines は SKILL.md:371 にある。以下のどちらかに移動:

- **案A**: Quick Start の直後（セクション2）に移動。スキル利用の最初の読み物として配置
- **案B**: Command Templates の直後（約160行目付近）に移動。具体的 API 呼び出しを見た直後に運用ルールを読ませる

案A の方が影響は大きいが、案B の方が改修コストが低い。

### 4. Command Templates セクションの補足

Command Templates 内の `is:unread` を使った例の直後に、以下の注記を1箇所追加:

```markdown
> **Note**: `is:unread` is useful for "new mail since last check" workflows, but
> NOT for "emails that need a reply". For the latter, see the Email Review Guidelines
> section below.
```
