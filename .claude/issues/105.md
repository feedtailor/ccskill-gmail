## 概要

ユーザーの audit.jsonl を分析し、頻出パターンからレシピ候補を提案・生成する recipe-creator を MVP として実装する。起動はユーザーの明示的呼び出しのみ。

## 背景

#102 の構想に基づく Phase 3。#050 で既に導入された audit.jsonl を活用し、ユーザーの暗黙知を形式知 (レシピ) に変換する仕組みを提供する。

「使えば使うほどスキルが自分用に育つ」というブランディング軸になる機能であり、アドバイザリー月次セッションの「あなたの業務をレシピ化します」メニューを支える具体的実装。

## 実装内容

### 1. recipe-creator.md の作成

`.claude/skills/ccskill-gmail/recipe-creator.md` を新設:

- 起動条件: ユーザーが明示的に呼び出した時のみ (例: 「レシピ化できそうなものを教えて」「recipe-creator を起動」)
- 動作フロー: **検出 → 抽出 → 提案 → 対話 → 生成 → 登録**
- 対話プロトコル: レシピ名・目的・設定項目を段階的にヒアリング
- 生成後は `recipes/<new-name>/` に出力

SKILL.md には「レシピ化できそうなものを探して」等の依頼検出時に recipe-creator.md を参照、という導線を 1 段落追加。

### 2. パターン検出ロジック

audit.jsonl のパース・集計を既存の history.sh 相当の仕組みで実装:

- 同一 action シーケンスが N 回以上繰り返されているもの
- 検索クエリの類似性 (同じ query が多用されている等)
- 頻度 Top 5 を抽出して提示

最初は単純な頻度ベースで OK。精度向上は Phase 4 以降で検討。

### 3. recipe-creator-templates/

レシピ生成時に使うテンプレート群を `.claude/skills/ccskill-gmail/recipe-creator-templates/` に配置:

- `README.md.tmpl`
- `prompt.md.tmpl`
- `example-output.md.tmpl`

ヒアリング結果 (レシピ名・目的・action シーケンス・設定値) を差し込んで `recipes/<new-name>/` に出力。必要に応じて `config-sample.js` / `automation.sh` のテンプレも追加。

### 4. 生成レシピの即利用

recipe-creator が生成したレシピは、Phase 2 (#104) の発動機構でそのまま利用可能。必要なら install フロー (スラッシュコマンド登録) も対話の最後にオファーする。

## プライバシー

- audit.jsonl は action 名と ID のみ (#050 の設計) なのでメール本文は含まれない
- recipe-creator の提案内容・生成レシピにもメール本文を含めない (原則維持)
- 提案に含まれるのは action のメタ情報と頻度のみ

## スコープ外 (Phase 4 で対応)

- 会話履歴 (`~/.claude/projects/`) 参照
- 時系列規則性検出 (毎週月曜朝、等)
- 能動提案 (ccskill-gmail 通常利用中に「これレシピ化しませんか」と AI から投げる)
