## 概要

`create_draft` の `to` フィールドに全角文字を含む文字列を**メールアドレスとして**渡した場合、GAS 側でエラーにならずそのまま処理され、Gmail 上で宛先・件名が文字化けする。

一方、RFC 5322 の **name-addr 形式**（`"表示名" <addr-spec>`）で日本語 display-name を指定した場合は GmailApp が正しく処理し、**文字化けしない**ことを実機で確認済み。

## 再現ケース

```json
// NG: addr-spec に全角文字 → 文字化け
{ "to": "【要入力】@kishidajim.co.jp" }

// OK: name-addr の display-name に全角文字 → 正常表示 (2026-06-13 実機確認)
{ "to": "\"岸田様\" <placeholder@kishidajim.co.jp>" }
```

## 検証結果 (2026-06-13)

`"岸田様" <oishi+kishida-test@feedtailor.jp>` で下書きを作成 → Gmail 上で To 欄に `岸田様 (oishi+kishida-test@feedtailor.jp)` と正しく表示された。GmailApp は name-addr 形式の display-name を RFC 2047 で適切にエンコードする。

## 実装内容

### 1. GAS 側バリデーション（addr-spec 部分のみを検査）

- `to` / `cc` / `bcc` を parse し、**addr-spec 部分**（`<...>` 内、または name-addr 形式でない場合の全体）に ASCII 範囲外の文字が含まれる場合のみエラーを返す
- display-name 部分の非ASCII はエラーにしない（正常動作するため）
- エラー例: `"'to' contains non-ASCII characters in the address part. Use name-addr format: \"表示名\" <address@example.com>"`

### 2. `reference/draft.md` への追記

以下を `create_draft` の Notes として追加:

- `to` / `cc` / `bcc` に日本語などの表示名を付けたい場合は name-addr 形式を使う: `"\"岸田様\" <kishida@example.co.jp>"`
- addr-spec 部分（`@` を含むアドレス本体）は必ず ASCII のみにすること
- 宛先が未確定の場合は英字のプレースホルダーを使う: `"\"岸田様\" <placeholder@kishidajim.co.jp>"`

### 3. `reference/limitations.md` への追記

- `to` の addr-spec に非ASCII文字を含めると文字化けが発生する（GmailApp の制約）
- name-addr 形式 `"表示名" <addr>` は正常動作する

- `gas-template/utils/validation.js` に純粋関数を追加:

- display-name の非ASCII は許容し、addr-spec のみ ASCII を要求
