## 概要

`ccskill-gmail` のローカル clone が origin/main に対して古くなっていることを、既存のユーザーコマンド実行時に自動的に検知して通知する機能を追加する。

#097 のような「知らずに壊れたまま使い続ける」ケースや、新規ユーザーが古い master から install してしまうケースを防ぐのが目的。

## 背景

- ccskill-gmail は git clone で配布されており、更新は `git pull` + `ccskill-gmail update` という手動の2ステップ
- ユーザーは「更新の有無」を能動的にチェックする動機がない限り気付けない
- 実際 #097（update.sh のディレクトリ平坦化バグ）のような修正が入っても、既存ユーザーには伝わらなかった
- 一方で、スキル実行時（`.ccskill-gmail/api` 呼び出し時）に毎回ネットワークアクセスするのは local-first の信頼モデルを壊すので避けたい

## 設計方針

### 原則

1. **人間が走らせるコマンドのみにチェックを仕込む** — `SKILL.md` レベルの自動トリガーからは明示的に除外する
2. **GitHub API を使わない** — `ccskill-gmail` 自体が git clone なので、`git fetch origin main` + `git rev-list --count HEAD..origin/main` で十分。認証不要、レート制限なし
3. **daily キャッシュ** — 1日1回しか fetch しない（毎コマンドで走らせない）
4. **失敗は silent** — ネットワーク不通・fetch エラー時は何も表示せず通常動作
5. **opt-out 可能** — `config.js` または環境変数で無効化できる

### 実装範囲

#### 1. 共通ヘルパー `lib/update_check.sh`（仮称）

- 関数: `check_remote_updates()` — fetch + rev-list で「N コミット遅れ」を返す
- キャッシュ: `~/.cache/ccskill-gmail/remote-check.json` に `{checked_at, commits_behind, latest_subject}` を保存
- キャッシュが 24h 以内なら再 fetch しない
- `ccskill-gmail` のインストール元 master path (`.ccskill-metadata.json` の `installed_from` 参照) に対して実行

#### 2. 各コマンドへの組み込み

| コマンド | 組み込み方 |
|---|---|
| `info` | 末尾に「Updates available: N commits behind (latest: xxx)」を表示 |
| `status` | サマリ末尾に同様の一行 |
| `doctor` | 診断項目の1つとして明示的にチェック。古い場合は `fix: git pull && ccskill-gmail update-all` をサジェスト |
| `help` | 末尾に daily キャッシュ結果を1行だけ表示（fetch は走らせない、キャッシュ読むだけ） |
| `install` | **重要** — install 実行前にチェックして、古い場合は「ローカルが N コミット遅れています。`git pull` してからインストールしますか？ [y/N]」で確認 |

#### 3. 設定

- `config.js` に `updateCheck: { enabled: true, intervalHours: 24 }` を追加
- 環境変数 `CCSKILL_GMAIL_NO_UPDATE_CHECK=1` で即時無効化

### スコープ外

- `SKILL.md` / `.ccskill-gmail/api` 呼び出し時の自動チェック
- GitHub API / リリース API の利用
- 自動更新（ユーザー同意なしに `git pull` を実行すること）
- プッシュ通知やバックグラウンド監視
