# セキュリティ設計判断

このドキュメントは、セキュリティレビューで検討した上で**意図的に不採用とした対策**と、その理由を記載する。
今後のレビューやコントリビューションで同じ議論が繰り返されることを防ぐ目的で明文化している。

## 前提

ccskill-gmail は**個人用ローカルツール**である。組織的な展開や SaaS 提供は現時点では想定していない。
この前提が変わった場合、以下の判断は再評価が必要。

## 不採用項目

| 項目 | 判断 | 理由 |
|------|------|------|
| GAS 側に `Session.getActiveUser()` チェック追加 | 不採用 | `access: "MYSELF"` が Google インフラレベルで強制される。`ANYONE` に変更した場合 `getActiveUser()` は空を返しうるため、二重チェックとして機能しない |
| `.env` の `source` を `grep` に変更 | 不採用 | `.env` はインストーラが自動生成するローカルファイル。改ざんできる攻撃者はスクリプト自体も改ざん可能であり、攻撃面の縮小にならない |
| 権限の既定値を read-only に変更 | 不採用 | 個人用ツールの主要ユースケース（検索→下書き返信→ラベル整理）が初期状態で動作しなくなる。`config.js` の `permissions.deny` で個別制限可能 |
| HTML/添付取得を既定 deny に変更 | 不採用 | Gmail スキルの機能要件（メールの閲覧）と矛盾する。HTML はデフォルト応答から除外済み（`get_message_html` で opt-in） |
| GAS 側に action 単位の監査ログ追加 | 不採用 | Stackdriver logging が有効。ローカル側の Audit Log（#050）で代替済み |

## 採用した対策

採用した対策の一覧は issue #049 および実装コードを参照。主な対策:

- `formatMessage` から `htmlBody` を除外（HTML 攻撃面の排除）
- ゼロ幅文字の自動除去（`stripInvisibleChars`）
- メール本文の境界マーカー（`EMAIL CONTENT START/END`）
- SKILL.md への間接プロンプトインジェクション注意書き
- `escapeHtml_` のシングルクォートエスケープ追加
- `.gitignore` 自動設定（install 時）
