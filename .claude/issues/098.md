## 概要

`get_thread` のレスポンスに、下書き (`isDraft: true`) を除外した「最終送信済みメッセージ」を表す `lastSentMessage` フィールドと、スレッドに下書きが含まれているかを表す `hasDraft` フラグを追加する。

これにより triage 系ワークフローで Claude が `messages[-1]` を素で参照して下書きを「送信済み返信」と誤判定する事故を、**プロンプト依存ではなく構造的に防ぐ**。

## 背景: 発生した事故

2026-04-14 の cron 実行で以下の誤判定が発生:

1. 加藤様スレッドに対してお礼返信の下書きを作成 (`create_reply_draft` → draftId `r-3041823515574754372`)
2. 次の cron サイクルで `get_thread` を呼び、「最終メッセージ送信者 = 自分」を根拠に "返信済み放置" と判定
3. 一括 archive の可否を確認 → ユーザーが「あれ、下書き作ってもらったばかりですよね？」と指摘
4. 調査の結果、`get_thread` の `messages[-1]` は送信済みメッセージではなく作ったばかりの**下書き**だった

## なぜ doc-only では不十分か

当初は「triage.md に `isDraft` 除外ルールを書けば良い」という doc-only 案だったが、ftgmail 側エージェントとレビュワーの議論で以下が確認された:

1. **プロンプト層の防御は本プロジェクトの "Defense in Depth" 思想と整合しない** (security-decisions.md 参照)
2. **同じセッション内で複数回 `messages[-1]` を素参照していた事例**があり、ルールを書いても忘れる確率が高い
3. **jq フィルタの運用は対話 Bash 規約 (`$()` / パイプ禁止) と相性が悪く**、レスポンスを素で読む流れになりがち
4. **守らせるのが難しいルールを書くより、データ側で表現する方が筋が良い**

## 改善内容

### 変更対象: `gas-template/utils/gmail.js` の `formatThreadWithMessages`

現状 (gmail.js:38-54):

```javascript
function formatThreadWithMessages(thread) {
  const messages = thread.getMessages();

  return {
    id: thread.getId(),
    subject: stripInvisibleChars(messages[0].getSubject()),
    messageCount: messages.length,
    isUnread: thread.isUnread(),
    isImportant: thread.isImportant(),
    isInPriorityInbox: thread.isInPriorityInbox(),
    isInInbox: thread.isInInbox(),
    labels: thread.getLabels().map(function(label) {
      return label.getName();
    }),
    messages: messages.map(formatMessage)
  };
}
```

改善後:

```javascript
function formatThreadWithMessages(thread) {
  const messages = thread.getMessages();
  const formattedMessages = messages.map(formatMessage);

  // Find last non-draft message (drafts appear inline with sent messages in the thread)
  var lastSentMessage = null;
  for (var i = formattedMessages.length - 1; i >= 0; i--) {
    if (!formattedMessages[i].isDraft) {
      lastSentMessage = formattedMessages[i];
      break;
    }
  }

  return {
    id: thread.getId(),
    subject: stripInvisibleChars(messages[0].getSubject()),
    messageCount: messages.length,
    isUnread: thread.isUnread(),
    isImportant: thread.isImportant(),
    isInPriorityInbox: thread.isInPriorityInbox(),
    isInInbox: thread.isInInbox(),
    labels: thread.getLabels().map(function(label) {
      return label.getName();
    }),
    messages: formattedMessages,
    lastSentMessage: lastSentMessage,
    hasDraft: formattedMessages.some(function(m) { return m.isDraft; })
  };
}
```

### 設計判断

- **`lastSentMessage` は `formatMessage` の出力をそのまま入れる** (object 全体)
  - 件名・本文・date・from など全てが取れるため triage 用途で柔軟
  - flat フィールド (`lastSentMessageFrom`, `lastSentMessageDate` 等) より拡張不要
- **全部 draft の場合は `null`** (`messages[-1]` を fallback にしない)
- **`hasDraft` は単純な bool**
  - 「下書きがある」というシグナルが必要十分。誰の下書きかが知りたい場合は `messages[]` から `isDraft: true` を探せば良い
- **`messages.map(formatMessage)` は `formattedMessages` にメモ化**して二度評価を避ける
