# セキュリティ設計判断

[English version](security-decisions.md)

このドキュメントは、セキュリティレビューで検討した上で**意図的に不採用とした対策**と、**採用したセキュリティ対策の包括的一覧**を記載する。
今後のレビューやコントリビューションで同じ議論が繰り返されることを防ぐ目的で明文化している。

## 前提

ccskill-gmail は、Claude.ai / Codex の標準 Gmail コネクタを補完する**個人用ローカル companion ツール**である。標準コネクタの代替ではなく、組織的な展開や SaaS 提供も現時点では想定していない。これらの前提のいずれかが変わった場合、以下の判断は再評価が必要。

## 設計原則

セキュリティモデル全体の基盤となる制約:

- **送信 API を不提供** — 下書き作成のみ。ユーザーが Gmail で確認してから送信する。AI による意図しないメール送信のリスクを構造的に排除。
- **永久削除 API を不提供** — `move_to_trash` のみ提供し、それも `config.js` でデフォルト deny。AI 操作による不可逆なデータ喪失を防止。
- **Web App は Google アカウントごとに 1 つ、MYSELF アクセス** — 中央アカウントレジストリ (#121〜#126) 以降、Web App は登録アカウントごとに 1 つデプロイされ全ディレクトリで共有される。`MYSELF` アクセス制限は不変で、変わったのはデプロイの粒度（プロジェクト単位 → アカウント単位）のみ。プロジェクト専用デプロイは `ccskill-gmail install --dedicated` で引き続き利用可能（プロジェクト別の `config.js` 権限制御など）。

## 採用したセキュリティ対策

以下の技術的対策を実装済み。各項目に対応する issue 番号を併記している。

| # | 対策 | issue |
|---|------|-------|
| 1 | GAS Web App を `MYSELF` アクセスに制限 — デプロイしたユーザーのみがエンドポイントを呼び出せる | #026 |
| 2 | `config.js` の allow/deny パーミッション機構、`move_to_trash` をデフォルト deny | #041 |
| 3 | `formatMessage` から `htmlBody` を除外 — デフォルト応答から HTML 攻撃面を排除 | #049 |
| 4 | ゼロ幅文字の自動除去（`stripInvisibleChars`）— メール本文・件名からゼロ幅スペース・結合子・方向制御文字を除去 | #049, #061 |
| 5 | メール本文の境界マーカー（`EMAIL CONTENT START/END`）— AI がメール内容とユーザー指示を区別しやすくする | #049 |
| 6 | SKILL.md への間接プロンプトインジェクション注意書き — メール内容に埋め込まれた指示に従わないよう AI に指示 | #049 |
| 7 | `escapeHtml_` にシングルクォートエスケープを追加 | #049 |
| 8 | install 時の `.gitignore` 自動設定 — `.ccskill-gmail/` のコミットを防止 | #049 |
| 9 | ローカル操作監査ログ（`history.sh`）— 全 API 操作を JSONL 形式でローカルに記録 | #050 |
| 10 | POST 用 JSON 一時ファイルを `.ccskill-gmail/tmp/` に格納 — `/tmp/` 汚染の回避と sandbox 互換性の向上 | #085 |
| 11 | Bulk 操作に `isActionAllowed` パーミッションチェックを適用 | #057 |
| 12 | Bulk 操作に `dryRun` オプションを提供 — 実行前の安全なプレビュー | #057 |

### 多層防御（プロンプトインジェクション対策）

プロンプトインジェクション対策は多層防御を構成している:

```
Layer 1: htmlBody をデフォルト応答から除外（HTML ベースの攻撃面を根絶）
Layer 2: ゼロ幅文字除去（プレーンテキストでの隠蔽を防止）
Layer 3: コンテンツ境界マーカー（AI の判断を補助）
Layer 4: SKILL.md の注意書き（AI への直接指示）
Layer 5: get_message_html は明示的 opt-in（必要時のみ HTML 取得）
```

## レビュー指摘のうち不採用とした項目

以下の項目はセキュリティレビューで指摘されたが、意図的に不採用とした。各項目に指摘内容と不採用の理由を記載している。

| 指摘項目 | 判断 | 理由 |
|----------|------|------|
| GAS 側に `Session.getActiveUser()` チェックを追加すべき | 不採用 | `access: "MYSELF"` が Google インフラレベルで強制される。`ANYONE` に変更した場合 `getActiveUser()` は空を返しうるため、二重チェックとして機能しない |
| 権限の既定値を read-only に変更すべき | 不採用 | 個人用ツールの主要ユースケース（検索→下書き返信→ラベル整理）が初期状態で動作しなくなる。`config.js` の `permissions.deny` で個別制限可能 |
| HTML/添付取得を既定 deny に変更すべき | 不採用 | Gmail スキルの機能要件（メールの閲覧）と矛盾する。HTML はデフォルト応答から除外済み（`get_message_html` で opt-in） |
| GAS 側に action 単位の監査ログを追加すべき | 不採用 | Stackdriver logging が有効。ローカル側の Audit Log（#050）で代替済み |
| `installed_from` パスの検証（realpath、uid チェック等）を追加すべき | 不採用 | `.ccskill-metadata.json` を改ざんできる攻撃者は `api` スクリプト自体も改ざん可能（同一ディレクトリ・同一パーミッション）。間接参照のパス検証は攻撃面の縮小にならない（#060 レビュー時に議論） |
| `api` スクリプトへのマスターパスをハードコードすべき | 不採用 | 上記と同じ理由で `installed_from` 間接参照と実質的な安全性は同等。metadata.json からの読み取りの方がメンテナンス性が高い |
| Bulk 操作に件数上限を設けるべき | 不採用 | GAS の6分実行時間制限が自然な上限として機能する。人為的な制限を加えても実用性が低下するだけでセキュリティ上の意味のある改善にならない |
