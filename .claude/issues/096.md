## 概要

SKILL.md / search.md / thread.md / label.md のチュートリアル例やコマンドテンプレートで `is:unread` が「メールを探す典型クエリ」として多用されている。これは動作確認用のサンプルとしては妥当だが、**Claude が文脈内の頻度から "メールを探す = is:unread が標準" と学習**してしまい、要返信 pickup のような別用途でも無批判に `is:unread` を付ける原因になる。

## 現状調査

`is:unread` の出現箇所（主要なもの）:

- `SKILL.md`: 11 箇所以上（Quick Start / Gmail Search Queries / Command Templates / Workflow Example）
- `SKILL.ja.md`: 同様
- `search.md:20` / `search.md:35` / `search.md:58` / `search.md:72` / `search.md:83` / `search.md:99`
- `thread.md:96-97` - "1. Search for unread emails" として最初の例で登場
- `label.md:96-97` - 同上
- `read.md` - `get_unread_count` 関連（これは API 仕様なので妥当）

## 問題の本質

`is:unread` 自体は正しい API の使い方であり、削除する必要はない。問題は**用途の文脈付けが欠けている**ことにある。Claude は以下のどちらの用途でも `is:unread` を使ってしまう:

- ✅ 正しい用途: 「前回チェック以降の新着を見る」「未読件数を調べる」
- ❌ 誤った用途: 「要返信メールを探す」「未返信のメールを探す」

## 改善内容

### 1. チュートリアル例の用途ラベル付け

`thread.md:96` / `label.md:96` の "Search for unread emails" を用途明記に変える:

```markdown
# 1. Get the latest unread email (for demo / smoke test — NOT for triage)
.ccskill-gmail/api get action=search query="is:unread" maxResults=1
```

### 2. search.md に「use-case map」セクションを追加

search.md の冒頭付近に、用途と推奨クエリの対応表を追加:

```markdown
## Use-case query map

| What you want | Recommended query | Do NOT use |
|---------------|-------------------|------------|
| New mail since last check | `is:unread in:inbox newer_than:1d` | — |
| Unread count only | `get_unread_count` action | — |
| **Emails that need a reply** | `in:inbox -from:me newer_than:7d -category:promotions -category:social -category:updates -category:forums` | ❌ `is:unread` |
| Automated bill/receipt triage | `from:<sender> subject:invoice` | — |
| Find a specific thread | `from:<sender> subject:<keyword>` | — |

See [triage.md](triage.md) for the full "emails that need a reply" workflow.
```

### 3. Gmail Search Queries セクションの強化

SKILL.md の Gmail Search Queries セクション（`is:unread` の用法を並べているところ）に注記を追加:

```markdown
> **When NOT to use `is:unread`**: Finding emails that need a reply. Once the user
> previews a message in any Gmail client, it becomes read — so `is:unread` misses
> most real "awaiting reply" threads. Use the query pattern in [triage.md](triage.md)
> instead.
```

### 4. Workflow Example の差し替えまたは追加

SKILL.md の "Workflow Example" セクション (`.ccskill-gmail/api get action=search query="is:unread"`) の隣に、**要返信 pickup ワークフロー**の例を追加:

```markdown
### Pickup emails that need a reply

\`\`\`bash
# 1. Get candidate threads (human senders, last 7 days)
.ccskill-gmail/api get action=search query="in:inbox -from:me newer_than:7d -category:promotions -category:social -category:updates -category:forums" maxResults=30

# 2. For each thread, check whether the last message is from the user
.ccskill-gmail/api get action=get_thread threadId=THREAD_ID
# ↑ inspect .data.messages[-1].from — if NOT the user, it's a reply candidate

# 3. Create a reply draft
.ccskill-gmail/api post '{"action":"create_reply_draft","threadId":"THREAD_ID","body":"..."}'
\`\`\`
\`\`\`
```

## 出典

2026-04-14 の運用事故の原因分析。`is:unread` がドキュメント内で文脈的に「メール検索の標準クエリ」として扱われており、LLM の頻度バイアスを誘発していることに合意。
