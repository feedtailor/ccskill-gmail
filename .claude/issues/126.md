## 概要

新方式 (account add + bind + skill install) が安定した後の仕上げ。install コマンドの位置づけを再定義し、README を新アーキテクチャ前提に再構成する。実施は任意 — #125 までで要求 (A)(B) は完結しており、本 Phase は負債整理の性格。全体方針は #121 を参照。

## 実装内容

1. **install の内部置換** — `ccskill-gmail install` を「account add (未登録時) + bind + プロジェクト permission 追記」の合成コマンドに作り直す。GAS の毎回新規作成をやめる。旧形式 (.ccskill-metadata.json) の読み取り互換は維持
2. **deprecation 経路の整理** — それまでの間 install 実行時に新方式推奨の notice を表示 (このタイミングは #123-#125 のリリースに合わせて前倒し可)
3. **README / README.ja の再構成** — Installation を「setup → account add → skill install」の流れに書き換え。マルチアカウント節を新方式で書き直し。config.js がアカウント単位になるトレードオフと、プロジェクト別権限を絞りたい場合のレガシー install 継続利用を明記
4. **docs/security-decisions.md 更新** — 「1 エンドポイント = 1 アカウント (MYSELF)」は不変でエンドポイントの粒度のみ変わったことを記録
5. **uninstall の掃除支援** — レガシー install の重複 GAS デプロイ一覧と手動削除の案内 (`account remove --purge` でのアンデプロイ対応もここで検討)
6. **レガシーメタデータの掃除手段（中央モードへの完全移行）** — migrate はレガシー `.ccskill-metadata.json` を安全のため残置するが、その結果「binding.json を unbind するとレガシーメタデータにフォールバックし、削除予定の旧専用デプロイを向いてしまう」現象が起きる（2026-06-11 に ftgmail で実例。ユーザーは default 解決を期待していた）。「このプロジェクトのレガシー残骸を取り除き中央モードに完全移行する」コマンドまたは uninstall のオプションを用意する。account_source での由来区別は #120 検討 6 を参照

## 実装記録 (2026-06-11)

- **install 再定義**: デフォルトは「アカウント解決 (--account 指定 > デフォルト) + bind + スキル/api 配置 + permissions opt-in + registry 登録」の軽量パス (GAS 新規作成・ブラウザ認可なし、数秒)。アカウント未登録なら `account add` を案内して非ゼロ終了。`--dedicated` (および `--user` 指定時は暗黙) で従来のプロジェクト専用 GAS 作成パスを温存 (#121 のトレードオフ尊重)
- **`account update [--all相当|<ident>] [--force]` 新設**: アカウント共有 GAS のコード push + デプロイ更新。これが無いと共有 GAS を更新する手段が存在しないギャップがあった。migrate 登録アカウント (ローカル gas ディレクトリなし) も accounts.json の script_id から .clasp.json を再構成して更新可能。update-all の冒頭で自動実行
- **update のセントラルモード対応**: binding.json のみのプロジェクトはファイル更新 + permissions + registry のみで完走 (GAS push/デプロイをスキップ)
- **`unbind --purge-legacy`**: レガシー install ファイル (metadata/.clasp.json/config.js/endpoint/api 等) を除去して中央モードへ完全移行。audit.jsonl は保持。通常の unbind ではレガシー残置を警告 (前日の「unbind したのに binding のまま」の根治)
- **migrate の config.js 引き継ぎ**: 代表プロジェクトの config.js をアカウント GAS ディレクトリへコピー (account update がテンプレートで上書きする事故の防止)。実環境にも適用済み
- **registry.sh**: mktemp を同一ディレクトリ tmp + atomic mv に変更 (sandbox 耐性)、CCSKILL_GMAIL_REGISTRY_FILE 上書き対応 (テスト用)
- **README / README.ja 全面改訂**: Installation = setup → account add → skill install、複数アカウント節・update・uninstall・Other commands・Architecture・Troubleshooting を新アーキテクチャに更新
- **security-decisions (両言語)**: 設計原則に「Web App はアカウントごとに 1 つ、MYSELF 不変、粒度のみ変更」を追記
- テスト: test-install-central.sh (9) 新規、test-bind-cmd.sh +2、test-migrate.sh +1。全 12 スイート green
- 実機確認: `account update` で 3 アカウントの共有 GAS を実 push + デプロイ (デプロイ ID 維持)、`--account info@feedtailor.jp` の実呼び出しが ok (migrate 登録アカウントが再認可なしで完全動作)
