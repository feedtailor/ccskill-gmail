## 概要

`ccskill-gmail update` を実行したとき、対象範囲のコミットに `feat:` / `fix:` が**1件もない**場合に、変更件数表示が壊れる。

```
Changes (0
0):
--------
  (Unable to show changes)
```

`Changes ($N):` の `$N` 部分に `0` が改行を挟んで2つ表示される。`Changes (1):` のようにあるべき形が崩れる。

## 再現条件

`docs:` / `chore:` / `test:` / `refactor:` だけのコミットを範囲に含む update。例えば本 issue を提起したきっかけは:

```
$ ccskill-gmail update
Current version: e8a02ca
Latest version:  bd8bbe4

Changes (0
0):
```

`e8a02ca..bd8bbe4` の差分は `docs: issue #111 を完了に更新` の 1 コミットのみで、これは feat/fix どちらでもないので集計対象 0 件。

## 原因

`commands/update.sh:149`:

```bash
TOTAL_COMMITS=$(cd "$CCSKILL_GMAIL_DIR" && git --no-pager log --no-merges --format="%s" "${CURRENT_VERSION}..${GLOBAL_VERSION}" 2>/dev/null | grep -cE "^(feat|fix):" || echo "0")
```

挙動の分解:

- `grep -c` はマッチ 0 件のとき**標準出力に `0` を吐き、exit 1 を返す**
- `|| echo "0"` が exit 1 を見て**追加で `0` を出力**
- 結果 `TOTAL_COMMITS` が `"0\n0"`（2 行）になる
- `echo "Changes ($TOTAL_COMMITS):"` がそのまま展開され `Changes (0\n0):` と見える

マッチが 1 件以上ある場合は grep が exit 0 で抜けるため `||` が発火せず、表示は正しくなる。だから今まで気付かなかった。

## 改善策

### 最小修正

```bash
TOTAL_COMMITS=$(... | grep -cE "^(feat|fix):" || true)
```

`grep -c` は既にマッチ 0 件でも `0` を出力するので、`||` 側で改めて値を出力する必要は無い。exit code を握り潰すだけで十分。

`set -e` 環境下でもパイプラインの最終 exit code が 0 になるため副作用なし。

### 代替案（採用しない）

- `wc -l | tr -d ' '` を使う方法もあるが、`grep -c` で完結している現状から余計な変更が増える
- 関数化（`count_user_facing_commits`）してから fix する案もあるが、1 行のバグ修正に対しては overspec

## 完了条件
