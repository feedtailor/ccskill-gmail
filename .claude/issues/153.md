## 概要
`commands/doctor.sh` の「clasp login」判定が、`_clasp show-authorized-user` の出力に「not logged in」という文字列が含まれるかどうかだけで PASS/FAIL を決めている。そのため、コマンド自体が別の理由（環境不備・実行時エラー等）で失敗し、出力が「not logged in」という文言を含まない場合、無条件に PASS（ログイン済み）と誤診断してしまう。


## 出典
本セッションでの実機調査（ccskill-gmailプロジェクト、2026-08-03）。


## 詳細
別プロジェクト（Obsidian notes）でのセッション中に、ccskill-gmail の Gmail 検索が
`Token refresh failed` エラーで失敗する事象が発生した。原因調査のため `ccskill-gmail doctor`
を実行したところ、以下の矛盾する診断結果が出力された。

- `clasp not available`（FAIL）
- `clasp logged in`（PASS）

`commands/doctor.sh` の該当箇所（62-84行目）は以下の通り。

```bash
# clasp
if _clasp --version &>/dev/null 2>&1; then
    ...
else
    echo -e "  $FAIL clasp not available"
    ...
fi

# clasp login（v3: show-authorized-user で判定）
if _clasp show-authorized-user 2>&1 | grep -qi "not logged in"; then
    echo -e "  $FAIL clasp not logged in"
    ...
else
    echo -e "  $PASS clasp logged in"
fi
```

`_clasp --version` が失敗するほど clasp の実行自体に問題がある状況でも、`_clasp show-authorized-user`
の出力（エラーメッセージ、モジュール読み込みエラー等）に「not logged in」という文字列が
たまたま含まれていなければ、else 節に落ちて無条件に「PASS clasp logged in」と表示されてしまう。
これは実行失敗の有無を判定しておらず、ログイン状態の判定として不正確である。

なお、今回の一次的な引き金は複数の環境要因（Homebrew の `clingo` フォーミュラが `clasp` という
エイリアスを持ち `brew reinstall clasp` で `/opt/homebrew/bin/clasp` が上書きされた事象、および
調査用サンドボックスの読み取り拒否パターンによる誤検知）が重なったものであり、本 issue の対象は
それらの環境要因そのものではなく、**doctor.sh 自身の判定ロジックが「実行失敗」と「未ログイン」を
区別できていない**という、環境要因とは独立して存在するコードレベルの不具合である。


## 方針
`_clasp show-authorized-user` の実行結果（終了コード、および実際にコマンドが実行できたか）を
明示的に確認し、以下の3状態を区別できるようにする。

1. clasp 実行自体が失敗する（コマンドが見つからない、実行時エラー等）→ FAIL として明示
2. clasp は実行できるがログインしていない（"not logged in" 文言を含む）→ FAIL clasp not logged in
3. clasp が正常に実行され、ログイン済みメールアドレスが取得できる → PASS clasp logged in（メールアドレスも表示）


## 実装内容
- `_clasp show-authorized-user` の終了コードを保持し、非ゼロ終了時は「not logged in」文字列の
  有無によらず FAIL 扱いにする
- 既存の `clasp_authorized_email` / `clasp_parse_authorized_email`（`lib/clasp.sh`）が使えないか
  確認し、パース結果が空文字なら FAIL、値が取れれば PASS として、メールアドレスの有無で判定する
  方式への変更を検討する（文字列マッチより頑健なため）


## スコープ外
- Homebrew の `clingo`/`clasp` エイリアス衝突そのものへの対処（doctor.sh の外側の環境要因であり、
  本 issue のスコープ外）
- サンドボックス環境の読み取り拒否パターンの調整（Claude Code 側の設定であり、本プロジェクトの
  スコープ外）
