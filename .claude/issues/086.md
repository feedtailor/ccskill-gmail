## 概要

`create_reply_draft` で `replyAll: true` を指定した場合、CC に自分自身のメールアドレス（認証ユーザのアドレス）が含まれてしまう。Gmail の UI で reply-all した場合は自分自身が自動除外されるが、GAS の `GmailApp.createDraft()` はこの除外処理を行わないため、下書きの CC に毎回自分のアドレスが残る。

## 再現手順

1. 自分宛て（To）に届いたメールに対して `create_reply_draft` を `replyAll: true` で実行
2. 作成された下書きの CC に自分のアドレスが含まれている

例:
- 元メール: From: aaa@example.com, To: oishi@feedtailor.jp, CC: bbb@example.com
- reply-all 下書き: To: aaa@example.com, CC: bbb@example.com, **oishi@feedtailor.jp** ← 不要

## 原因

GAS の `GmailApp.createDraft()` は reply-all 時に元メールの To + CC を機械的に CC に設定し、自分自身のアドレスを除外するロジックを持たない。Gmail UI のような「自分を除外」する処理は API 利用側で実装する必要がある。

## 修正方針

GAS サーバー側の `create_reply_draft` 処理で、CC リスト構築時に認証ユーザのアドレスを除外する。

1. `Session.getActiveUser().getEmail()` 等で認証ユーザのメールアドレスを取得
2. CC リストから当該アドレスを除外してから `GmailApp.createDraft()` に渡す
3. エイリアス（別名アドレス）がある場合も考慮が必要か検討

## 検証方法

1. 自分が To に含まれるメールに `replyAll: true` で返信下書きを作成
2. 下書きの CC に自分のアドレスが含まれていないことを確認
3. CC に含まれるべき他の宛先は正しく残っていることを確認
4. 自分が CC に含まれるメールへの reply-all でも同様に除外されることを確認
