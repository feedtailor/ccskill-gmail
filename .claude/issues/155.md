## 概要
[[154]] で確認した「GASの一時的な "ページが見つかりません" HTML応答」について、現状 `lib/api.sh`
の `ccskill-get` / `ccskill-post` には自動リトライの仕組みがなく、失敗がそのまま呼び出し側に
返っている。ドキュメント追記（[[154]]）だけでなく、呼び出し側（Claude や利用者）が気づかず
再試行する手間自体をなくすため、HTML応答を検知した場合に内部で自動リトライするコード改善を行う。


## 出典
本セッションでの実機調査（ccskill-gmailプロジェクト、2026-08-03）。7回のAPI呼び出し中3回、
GAS側から期待するJSONの代わりにHTMLが返る事象を確認した。いずれもサンドボックス無効化状態でも
発生しており、再試行すると必ず成功した。


## 詳細
現在の `ccskill-get` / `ccskill-post`（`lib/api.sh`）は、curl の応答をそのまま返しているだけで、
応答がHTMLであっても検知・リトライを行わない。

```bash
curl -sL --max-time 60 \
    -H "Authorization: Bearer $(gas_token)" \
    "$url"
```

呼び出し側（Claude Codeのセッションや将来の利用者）が、応答がJSONでなくHTMLであることに気づいて
手動で再実行する必要があり、気づかなければ「壊れている」という誤った印象を持ちかねない
（実際、本セッションでもこの現象を一度は「npm/claspパッケージの破損」という誤診断の材料に
してしまった）。


## 方針
`ccskill-get` / `ccskill-post` の内部で、応答が HTML（`<!DOCTYPE`/`<html` で始まる）に
見える場合、短い間隔を空けて最大3回まで自動的にリトライする。JSON形式のエラー応答
（`{"ok":false,...}` 等、アプリケーションレベルの正当なエラー）はリトライ対象にしない
（HTML かどうかだけで判定するため、自然にこの区別がつく）。


## 実装内容
- `_ccskill_looks_like_html BODY`: 応答の先頭が `<!DOCTYPE`/`<html`（大小文字区別なし）かどうかを
  判定する純粋関数
- `_ccskill_fetch_with_retry CMD...`: 任意のコマンド（1回のHTTP取得を行いボディをstdoutに出力する
  ものを想定）を実行し、結果がHTMLに見える場合は `_CCSKILL_RETRY_DELAY`（既定1秒、テストでは0に
  上書き可能）待ってから再試行する。最大3回試行し、最後の結果をそのまま返す
- `ccskill-get` / `ccskill-post` の curl 呼び出しを `_ccskill_fetch_with_retry` 経由に変更


## スコープ外
- GAS側の不調そのものの根本原因調査（Google側インフラのため対応不可）
- `_gmail_download` 等、`ccskill-get` を内部で呼ぶ既存ヘルパーの変更（`ccskill-get` 自体が
  リトライを内包するため、これらのヘルパーは変更不要のはず。実装後に動作確認する）

### 2026-08-03 (実装・完了)
新規 `lib/http_retry.sh` に `_ccskill_looks_like_html`（HTMLの先頭パターン判定）と
`_ccskill_fetch_with_retry`（任意コマンドを実行し、結果がHTMLに見える場合は
`_CCSKILL_RETRY_DELAY`（既定1秒）待って最大3回まで再試行）を実装。`tests/lib/test-http-retry.sh`
に9件のテストを追加（実装前に9件とも失敗することを確認 → 実装後に9件ともパス）。

テスト実装で1点つまずいた: フェイクの取得関数がシェル変数のカウンタをインクリメントする方式だと、
`_ccskill_fetch_with_retry` 内の `response=$("$@")`（コマンド置換 = サブシェル）を経由するため、
カウンタの変更が親シェルに伝播せず常に0のままだった。ファイルベースのカウンタ
（`test_mktemp` で作った一時ファイルに数値を書き込み/読み込み）に変更して解決。同種のテストを
今後書く際は、コマンド置換経由で呼ばれるフェイク関数の状態はシェル変数ではなくファイルで
持たせる必要がある点に注意。

`lib/api.sh` の `_ccskill_init` で `http_retry.sh` を読み込み（存在しない場合はエラーにせず
graceful degradation）、`ccskill-get` / `ccskill-post` の curl 呼び出しを
`type _ccskill_fetch_with_retry` の有無で分岐し、存在すればリトライ経由、なければ従来通り直接
curl を呼ぶよう変更（古いプロジェクトコピー install が本ファイルを持たない場合の後方互換のため）。

全シェルテスト・全JSテストが回帰なくパス。実機で `ccskill-gmail api get action=list_labels` /
`action=get_profile` を実行し、通常時の動作（レスポンス内容・速度）に影響がないことを確認した。
