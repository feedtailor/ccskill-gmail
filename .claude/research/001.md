# ccskill-spreadsheet の進化分析と ccskill-gmail への適用計画

## 1. エグゼクティブサマリー

ccskill-spreadsheet は 2026年1月末〜2月にかけて大幅に進化した。主要な変更は以下の通り:

| 領域 | 旧（gmail が現在採用中） | 新（spreadsheet が採用済） |
|------|--------------------------|---------------------------|
| GAS 権限 | `ANYONE_ANONYMOUS` | `MYSELF` + OAuth Bearer |
| スクリプト構成 | 単独の install.sh / update.sh / uninstall.sh | コマンドディスパッチャ + 9 サブコマンド |
| 認証 | なし（URL知れば誰でもアクセス可） | clasp OAuth トークン + 自動リフレッシュ |
| API 呼び出し | 生 curl（各スキルドキュメントにルール記載） | `ccskill-get` / `ccskill-post` ラッパー |
| エンドポイント保護 | なし | ホワイトリスト検証（script.google.com のみ） |
| デプロイ | 手動（GAS エディタで操作） | `push_gas` / `deploy_gas` 関数で自動化 |
| インストール管理 | 各プロジェクト独立 | `.registry.json` でグローバル追跡 |
| GAS コード配置 | プロジェクト内に src/ コピー | master アーキテクチャ（config.js のみローカル） |
| マニフェスト | webapp 設定なし | `webapp.access: "MYSELF"` 明示 |
| バリデーション | 定義済み未使用（106行） | 全ハンドラで活用（439行） |

**結論**: ccskill-gmail は「1ヶ月前の設計」のまま残っており、セキュリティ・運用性・保守性の全面で ccskill-spreadsheet に大きく後れを取っている。

## 2. 詳細比較分析

### 2.1 セキュリティモデル（最重要）

#### ccskill-gmail（現状）
```
デプロイ設定: "Anyone" (URL公開)
認証: なし
リスク: URL漏洩 = Gmail全アクセス可能
```

- `appsscript.json` に `webapp` セクションなし
- curl に Authorization ヘッダなし
- SKILL.md, examples.md, troubleshooting.md すべて認証なし前提

#### ccskill-spreadsheet（目標）
```
デプロイ設定: "MYSELF" (本人のみ)
認証: OAuth Bearer トークン（clasp 経由）
保護: エンドポイントホワイトリスト
```

- `appsscript.json`:
  ```json
  "webapp": {
    "access": "MYSELF",
    "executeAs": "USER_DEPLOYING"
  }
  ```
- `lib/auth.sh`: トークン取得 + 自動リフレッシュ（期限切れ60秒前マージン）
- `lib/api.sh`: `ccskill-assert-endpoint()` でドメインホワイトリスト検証
- すべての curl に `Authorization: Bearer $(gas_token)` 付与

#### 適用時の影響範囲
- `appsscript.json` - webapp セクション追加
- `SKILL.md` - curl テンプレート全書き換え
- `examples.md` - 全14例の curl 更新
- `troubleshooting.md` - 認証エラー対応追加
- `reference/*.md` - 全7ファイルの curl 更新
- `install.sh` - auth.sh / api.sh コピー追加、自動デプロイ対応
- `README.md` - セキュリティモデル説明更新

### 2.2 コマンド体系

#### ccskill-gmail（現状）
```
ccskill-gmail/
├── install.sh    (411行, スタンドアロン)
├── update.sh     (228行, スタンドアロン)
└── uninstall.sh  (224行, スタンドアロン)
```
- 各スクリプトが独立、共通処理の重複あり
- 環境変数 `$CCSKILL_GMAIL_DIR` で自身の場所を把握
- バージョン管理は各スクリプト内で git を直接参照

#### ccskill-spreadsheet（目標）
```
ccskill-spreadsheet           # メインディスパッチャ (90行)
├── commands/
│   ├── install.sh           # インストール
│   ├── uninstall.sh         # アンインストール
│   ├── update.sh            # 更新
│   ├── update-all.sh        # 一括更新
│   ├── apply-config.sh      # 設定反映
│   ├── register.sh          # 既存登録
│   └── status.sh            # ステータス確認
└── lib/
    ├── api.sh               # API ラッパー
    ├── auth.sh              # OAuth 認証
    ├── push-gas.sh          # GAS push/deploy
    ├── registry.sh          # レジストリ管理
    └── permissions.sh       # Claude Code 権限設定
```

- ディスパッチャパターン: `ccskill-spreadsheet <command> [args...]`
- 共通処理は `lib/` に集約
- `CCSKILL_SPREADSHEET_DIR` をディスパッチャが設定、全コマンドで共有

#### Gmail への適用計画
Gmail は spreadsheet と違ってマルチスプレッドシート概念がないため、`add.sh` / `remove.sh` は不要。以下が必要:

```
ccskill-gmail                 # メインディスパッチャ
├── commands/
│   ├── install.sh
│   ├── uninstall.sh
│   ├── update.sh
│   ├── update-all.sh
│   ├── apply-config.sh      # (config.js が空に近いので要検討)
│   ├── register.sh
│   └── status.sh
└── lib/
    ├── api.sh               # ccskill-get / ccskill-post
    ├── auth.sh              # gas_token()
    ├── push-gas.sh          # push_gas / deploy_gas
    ├── registry.sh          # レジストリ管理
    └── permissions.sh       # Claude Code 権限
```

### 2.3 デプロイ自動化

#### ccskill-gmail（現状）
- `install.sh` が `clasp create` → `clasp push --force` → ブラウザで手動デプロイ
- ユーザーが GAS エディタで "Deploy" → "New deployment" を手動操作
- デプロイ URL をターミナルに貼り付けて検証

#### ccskill-spreadsheet（目標）
- `lib/push-gas.sh` の `push_gas()` と `deploy_gas()` で完全自動化
- `push_gas`: temp ディレクトリで master テンプレート + プロジェクト config.js を合成 → `clasp push`
- `deploy_gas`: `clasp deploy` を実行し DEPLOYMENT_ID を自動取得・保存
- 更新時は DEPLOYMENT_ID を使って同じデプロイメントを上書き

#### 適用時のポイント
- Gmail でも同じ `push_gas` / `deploy_gas` パターンが使える
- Gmail の場合 config.js はほぼ空だが、将来の拡張性のため維持

### 2.4 レジストリシステム

#### ccskill-gmail（現状）
- なし。各プロジェクトの `.ccskill-gmail/.ccskill-metadata.json` に個別記録のみ

#### ccskill-spreadsheet（目標）
- `.registry.json`（リポジトリルート）で全インストール先をグローバル追跡
- `lib/registry.sh` で CRUD 操作
- `status.sh` で全インストール先の状態一覧表示
- `update-all.sh` で一括更新

#### 適用計画
- `lib/registry.sh` をほぼそのまま流用可能（パス名を gmail 用に変更）
- `status.sh` / `update-all.sh` も同様に流用

### 2.5 API ラッパー

#### ccskill-gmail（現状）
- SKILL.md に生の curl コマンドテンプレートを記載
- ユーザー（Claude）が毎回 curl のフラグを正しく組み立てる必要あり
- 日本語 URL エンコーディングも各所にルール記載

#### ccskill-spreadsheet（目標）
```bash
# lib/api.sh が提供する関数
ccskill-get "$ENDPOINT" action=search query="日本語検索"
ccskill-post "$ENDPOINT" '{"action":"create_draft","to":"a@b.com",...}'
```

- `ccskill-get`: key=value 形式で自動 URL エンコード、Bearer 認証自動付与
- `ccskill-post`: JSON ボディ or @file、Bearer 認証自動付与
- `ccskill-assert-endpoint`: ドメインホワイトリスト検証
- `_ccskill_init`: .env 読み込み + auth.sh 自動ロード

#### 適用時の影響
- `ccskill-get` / `ccskill-post` はドメイン非依存なのでそのまま流用可能
- SKILL.md の curl テンプレートをすべてラッパー形式に書き換え
- Claude Code permissions で `Bash(ccskill-get:*)` / `Bash(ccskill-post:*)` を自動設定

### 2.6 GAS コード配置アーキテクチャ

#### ccskill-gmail（現状）: コピーアーキテクチャ
```
install.sh: gas-template/ → .ccskill-gmail/src/ にフルコピー
update.sh: gas-template/ → .ccskill-gmail/src/ に上書き（config.js 保護）
clasp push: .ccskill-gmail/src/ から push
```
- 各プロジェクトに GAS コード全体のコピーが存在
- `.clasp.json` の `rootDir` は `"./src"`

#### ccskill-spreadsheet（目標）: マスターアーキテクチャ
```
push_gas: gas-template/ + project/config.js → temp dir で合成 → clasp push
deploy_gas: clasp deploy を temp dir で実行
```
- プロジェクトには `.clasp.json` + `config.js` のみ
- GAS コードはマスター（リポジトリ）にのみ存在
- push 時に毎回マスターから最新を合成

#### 適用メリット
- プロジェクト側のファイル数が大幅削減（src/ ディレクトリ不要）
- 更新時にファイルコピーの整合性問題が発生しない
- GAS コードの唯一の真実のソースがリポジトリに集約

### 2.7 Claude Code パーミッション自動設定

#### ccskill-gmail（現状）
- なし。ユーザーが手動で許可

#### ccskill-spreadsheet（目標）
- `lib/permissions.sh` の `setup_permissions()` が `.claude/settings.local.json` を自動更新
- `Bash(ccskill-get:*)` / `Bash(ccskill-post:*)` を追加
- install / update 時にオプトインで実行

### 2.8 バリデーション

#### ccskill-gmail（現状）
- `utils/validation.js` に7関数定義（106行）
- **ハンドラからは一切呼ばれていない**（review_20260206.md Issue 2）

#### ccskill-spreadsheet（目標）
- `utils/validation.js` に包括的なバリデーション（439行）
- 全ハンドラで適切に使用
- 型チェック、範囲チェック、フォーマットチェック

#### 適用方針
- Gmail 用バリデーションを実際にハンドラに組み込む
- 不要な汎用関数は削除し、Gmail 固有のバリデーションに特化

## 5. lib/ 共通化の可能性

`lib/auth.sh`, `lib/api.sh` は Gmail / Spreadsheet で完全に同一のコードが使える。将来的には共通ライブラリとして切り出す選択肢もあるが、現時点ではプロジェクトごとにコピーを持つ方がシンプル。

共通化候補:
- `auth.sh` - gas_token() は GAS Web App 共通
- `api.sh` - ccskill-get/post は GAS 共通
- `push-gas.sh` - push_gas/deploy_gas は GAS 共通
- `registry.sh` - パス名が異なるだけで構造は同一
- `permissions.sh` - パーミッションパターンが異なるだけ

## 6. Gmail 固有の考慮事項

### マルチスプレッドシート相当がない
- Spreadsheet: 複数スプレッドシートを名前付きで管理（`add.sh` / `remove.sh`）
- Gmail: 1アカウント = 1エンドポイント（マルチ概念不要）
- → `add.sh` / `remove.sh` は不要

### config.js の役割
- Spreadsheet: `CONFIG.SPREADSHEETS` でスプレッドシート ID を管理（必須）
- Gmail: `CONFIG` はほぼ空（Gmail はアカウントベースで ID 不要）
- → config.js は将来拡張用に維持するが、初期は最小限

### API ラッパーの命名
- 現在 spreadsheet は `ccskill-get` / `ccskill-post` を使用
- Gmail でも同じ名前を使用可能（関数はドメイン非依存）
- → プロジェクトごとに api.sh がロードされるため衝突なし

## 8. 補足: spreadsheet 側の注目パターン

### 自動初期化パターン（api.sh）
```bash
_ccskill_init() {
    # .env 読み込み
    # auth.sh ソース
    # 一度だけ実行
}
```
→ `source .ccskill-gmail/api.sh` だけで全準備完了

### デプロイ ID 管理
- install 時に `clasp deploy` で生成される DEPLOYMENT_ID を `.ccskill-metadata.json` に保存
- update 時に同じ DEPLOYMENT_ID を使って `clasp deploy -i $ID` で上書き
- → URL が変わらない（.env の ENDPOINT を再設定不要）

### レガシーマイグレーション
- update.sh に旧 src/ レイアウトからの自動移行コード
- → Gmail でも同様のマイグレーションパスが必要
