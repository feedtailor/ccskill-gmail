## 概要

#116 で SKILL.md をスリム化したあと、ftgmail で実機テストしたところ以下の問題が判明した:

1. **「最近のメールで返信すべきものは?」依頼に対して LLM が `is:unread` を直接使った** — triage.md で禁止のクエリなのに、SKILL.md の Quick Start に `is:unread` の例が残っていたため誤誘導された。triage.md は読みに行かれなかった。
2. **「先月の重要なメール」依頼に対して LLM が `is:important` (Gmail の重要マーカー) を素直に使った** — ユーザー意図は「人間判断で重要なもの」だったが、triage.md の発火条件 (L5-8) に「重要なメール」「ピックアップ」等のフレーズが無く、SKILL.md の navigation 表からも triage.md を引かなかった。
3. **LLM が triage.md を自発的に参照する経路が弱い** — Where to Find What 表だけでは「特定の依頼パターンで必ず参照すべきドキュメント」と認識されていない。

要するに #116 で SKILL.md から行動規範を削除した判断は概ね正しかったが、「LLM が triage.md に飛ぶ条件」が想定より狭かった。発火条件の拡張と誤誘導の排除で対応する。

## 修正内容

### A. Quick Start から `is:unread` の例を排除 (SKILL.md / SKILL.ja.md)

現状 Quick Start の例:

```bash
.ccskill-gmail/api get action=search query="is:unread"
```

→ `is:unread` を使わない別パターンに差し替える (例: `from:boss@example.com` / `subject:report` 等)。

**理由**: SKILL.md は常時 LLM の context に入る。Quick Start に `is:unread` が例示されていると、LLM はこれを「このスキルの標準クエリ」と誤学習する。triage.md の "Do NOT filter by is:unread" 警告と矛盾する。

### B. Where to Find What 表の triage 行に強制力を付与 (SKILL.md / SKILL.ja.md)

現状:

```
| Inbox triage / "emails that need a reply" workflow | reference/triage.md |
```

→ 「READ BEFORE constructing a search query」等の文言で強制力を持たせる。

**理由**: navigation 表のリンクは LLM が能動的に参照しないと機能しない。triage 系依頼を受けた瞬間に triage.md を読むよう誘導する文言が必要。

### C. triage.md の発火フレーズ拡張 + `is:important` 注意

`reference/triage.md` L5-8 の "When to use this document" に追加:

- 日本語: 「**重要なメール**」「**優先度の高いメール**」「**ピックアップ**」「**目を通すべきメール**」「**重要なやりとり**」
- English: "**important emails**", "**high-priority emails**", "**pick out the important ones**", "**what's important**", "**highlights**"

加えて、triage.md 冒頭に以下の注意書きを追加:

> **`is:important` (Gmail の重要マーカー) は人間判断の "重要" とは別物。** Gmail の自動付与で意味のあてにならないノイズが多い。triage 判定は本文・送信者・文脈から行うこと。

**理由**: 「重要なメール」という日本語自然発話は典型的な triage 依頼なのに発火条件から漏れていた。`is:important` への誤誘導も明示的に防ぐ。

## 実機テスト結果と追加修正の経緯

ftgmail で実機テストを実施したところ、A/B/C の修正だけでは不十分と判明:

| テスト | 結果 |
|---|---|
| 「返信すべきものは?」 | ✅ triage.md 到達、`is:unread` 不使用、`lastSentMessage` 使用 |
| 「メールチェックお願いします」 | ❌ triage.md 未到達、`is:unread` 使用、分類なし |

**判明した構造的問題**: Claude Code の skill 機構には条件付きロードが無く、navigation 表に「READ BEFORE...」と書いても LLM が能動的に triage.md を読まないケースが発生する。「is:unread を使うな」「lastSentMessage を読め」のような**短くて強力な行動規範**は SKILL.md inline 必須。

**追加修正**: #116 で navigation 委譲に追い出した以下のブロックを SKILL.md / SKILL.ja.md に復活させた:

- Email Review — Critical Rules (`is:unread` / `is:important` 禁止、`lastSentMessage` 使用、ベースクエリ、`newer_than:1d` 禁止)
- PDF Saving Guidance (3 段階優先順位)

その他 (Operation History / Shell Script Generation / Limitations) の navigation 委譲は維持。**「カタログは外出し / 行動規範は inline」の線引きが正しい**ことが実証された。

SKILL.md は最終的に 194 行 (元 550 行から大幅圧縮、目標 200 行以下達成)。
