## 概要

`~/.ccskill-gmail/accounts.json` による複数アカウントの中央登録と、`account` コマンド群・`--account` フラグを実装する。この Phase の完了で「install なしでも `account add` 1 回で全ディレクトリから利用可能」が CLI レベルで成立する。スキーマ・解決優先順位の詳細は #121 を参照。

## 実装内容

1. **`lib/accounts.sh` (新規)** — accounts.json の CRUD・アカウント解決ロジック。`lib/registry.sh` の実装パターン (jq + atomic write) を踏襲。ディレクトリ 700 / ファイル 600
2. **`lib/provision.sh` (新規)** — `commands/install.sh:262-435` の GAS プロビジョニング部 (clasp create → push → deploy → ブラウザ認可 → 検証) を関数化して抽出。install.sh は抽出後の関数を呼ぶ形に書き換え (挙動不変)
3. **`commands/account.sh` (新規)**
   - `account add [--label NAME]` — clasp login (--user は email から自動生成) → provision (GAS タイトル: `Gmail Skill - <email>`) → get_profile で email 確定 → accounts.json 登録。登録 1 件目は自動的に default_account
   - `account list` / `account default <email|label>` / `account remove <email>` (GAS は残す旨を案内)
4. **`lib/api` のアカウント解決チェーン完成** — #122 の解決順に続けて: `--account` フラグ (先頭のみ許可) > `CCSKILL_GMAIL_ACCOUNT` 環境変数 > (cwd メタデータ) > default_account > 登録 1 件ならそれ > `NO_ACCOUNT` エラー
5. **レスポンスへのアカウント注入** — ディスパッチ後に jq で `+ {"account": "<email>", "account_source": "flag|binding|default"}` をマージ (jq 不在時はスキップ)
6. **`api whoami`** — 解決されるアカウントと解決根拠を返す
7. **`lib/auth.sh` 小改修** — トークンリフレッシュ書き戻し失敗時もリフレッシュ済みトークンで処理続行できることを明示的に保証 (sandbox 内実行への縮退対応)
8. **`info` / `status` / `doctor` の対応** — アカウント解決結果の表示、accounts 一覧、accounts.json の診断
