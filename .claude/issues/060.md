## 概要

`.ccskill-gmail/` にマスターからコピーされるスクリプト（auth.sh, history.sh）を廃止し、
endpoint を .ccskill-metadata.json に統合、history/ ディレクトリを廃止して、
プロジェクト固有データのみが残るシンプルな構成にする。

## 背景

現状は `.ccskill-gmail/` にプロジェクト固有データとツールコードが混在している。
auth.sh / history.sh は全プロジェクトで同一内容で、update のたびにコピーし直す必要がある。
endpoint も独立ファイルだが、.ccskill-metadata.json に統合可能。

## Before（8ファイル + 1ディレクトリ）

```
.ccskill-gmail/
├── .clasp.json
├── .ccskill-metadata.json
├── endpoint                 # → metadata に統合
├── config.js
├── api*                     # ← コピー
├── auth.sh*                 # ← コピー（廃止）
├── history.sh               # ← コピー（廃止）
└── history/                 # → ディレクトリ廃止
    └── audit.jsonl
```

## After（5ファイル）

```
.ccskill-gmail/              # chmod 700
├── .clasp.json              # clasp 管理
├── .ccskill-metadata.json   # インストール情報 + endpoint
├── config.js                # 権限設定
├── api*                     # 唯一のスクリプト
├── audit.jsonl              # 操作履歴（直置き）
└── audit.jsonl.1            # ローテーション時のみ
```

## 変更内容

### 1. api スクリプトの変更
- `auth.sh` を `$SCRIPT_DIR` からではなく `$CCSKILL_GMAIL_DIR/lib/auth.sh` から source
- `history.sh` を `$CCSKILL_GMAIL_DIR/lib/history.sh` から source
- `endpoint` を `$SCRIPT_DIR/.ccskill-metadata.json` から jq で読み取り
- `audit.jsonl` の出力先を `$SCRIPT_DIR/audit.jsonl` に変更（history/ 廃止）

### 2. install.sh の変更
- `auth.sh` / `history.sh` のコピーを廃止
- `history/` ディレクトリ作成を廃止
- `endpoint` ファイル生成を廃止し、`.ccskill-metadata.json` に endpoint を含める
- `.ccskill-gmail/` を `chmod 700` に設定

### 3. update.sh の変更
- `auth.sh` / `history.sh` のコピーを廃止
- `history/` ディレクトリ作成を廃止
- 既存の `endpoint` ファイルを `.ccskill-metadata.json` に移行する処理を追加

### 4. history 関連の変更
- `_ccskill_history_rotate` のパスを `history/audit.jsonl` → `audit.jsonl` に変更
- `_ccskill_history_list` のパスも同様
- `commands/history.sh` のパス参照を更新

### 5. doctor.sh の変更
- `auth.sh` / `history/` のチェックを廃止
- `endpoint` ファイルチェックを `.ccskill-metadata.json` 内の endpoint チェックに変更
- 疎通チェックの auth.sh パスをマスター参照に変更

### 6. SKILL.md の変更
- 操作履歴の保存場所パスを `.ccskill-gmail/history/audit.jsonl` → `.ccskill-gmail/audit.jsonl` に更新

### 7. 後方互換
- update 時に旧 endpoint ファイルを検出したら `.ccskill-metadata.json` に移行
- 旧 auth.sh / history.sh を削除
- 旧 history/ ディレクトリは放置（既存の audit.jsonl は参照されなくなるが、データ損失ではない）

## 注意

api スクリプトがマスターの lib/ を直接参照するため、`CCSKILL_GMAIL_DIR` の解決方法が重要。
現状 api は `$SCRIPT_DIR` 基点で動作するが、マスターの場所を知る仕組みが必要。
`.ccskill-metadata.json` の `installed_from` フィールドにマスターパスが記録されているので、これを使う。
