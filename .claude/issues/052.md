# #052: htmlBody 未指定時の自動生成（改行消失防止）

## ステータス: 実装済み（テスト待ち）

## 概要

`create_draft` / `create_reply_draft` で `htmlBody` を省略し `body` のみ指定した場合、Gmail が内部 HTML 化する際に `\n` が `<br>` に変換されず、改行が消失する問題。

## 背景

実際の運用で発生。LLM エージェントが `create_reply_draft` に `body` のみ（`htmlBody` なし）で下書きを作成した結果、Gmail 上で改行が全て消えた状態で表示された。

- Gmail の下書き UI は常に HTML ベースで表示される
- GAS の `createDraftReplyAll(body, options)` は `options.htmlBody` がない場合、`body` の `\n` → `<br>` 変換を保証しない
- GAS コード自体にバグはないが、Gmail/GAS の仕様上の落とし穴

## 対策

GAS 側で `htmlBody` 未指定時に `body` から自動生成する。

### 対象関数

- `handleCreateDraft`（handlers/draft.js）
- `handleCreateReplyDraft`（handlers/draft.js）

### 実装方針

`buildEmailOptions` を呼ぶ前に、`htmlBody` が未指定かつ `body` が存在する場合、自動生成する:

```javascript
if (!htmlBody && body) {
  htmlBody = body
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/\n/g, '<br>');
}
```

- 呼び出し側が `htmlBody` を明示指定した場合はそちらを優先（既存動作を維持）
- `body` はそのまま MIME plain text パートとして残る（フォールバック用）
- 変換は HTML エスケープ + 改行変換のみ。URL 自動リンク化等は行わない（過剰変換を避ける）

### 検討事項

- `update_draft` の `handleUpdateDraft` にも同様の処理が必要か？ → `update_draft` は `htmlBody` 未指定時に既存の HTML を `message.getBody()` から引き継ぐ設計なので不要
- SKILL.md への注記追加は任意（GAS 側で吸収するため必須ではないが、「htmlBody を指定するとリッチな HTML メールが作れる」旨の補足は有用）

中。実運用で問題が発生済み。ただし LLM が `htmlBody` を付ける習慣があれば回避可能なため、緊急ではない。
