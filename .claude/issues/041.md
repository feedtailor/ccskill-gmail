## タスク概要

config.js に allow/deny ベースのパーミッション機構を導入し、破壊的かつ非可逆な操作をデフォルトで無効化する。

## 背景

AI エージェントが長時間の会話で compact（コンテキスト圧縮）を経験した際に、当初の指示が欠損して破壊的操作を意図せず実行するリスクがある。特に `move_to_trash` は 30日後に永久削除されるため、API レベルで防御する必要がある。

トークン方式（2段階確認）も検討したが、AI がトークンの使い方を SKILL.md から学習して自律的に実行できてしまうため、根本的な防御にならない。**API 自体をデフォルトで無効にする**のが最も確実。

## 設計

### パーミッションモデル（Claude Code の allow/deny パターン準拠）

```javascript
// config.js
const CONFIG = {
  permissions: {
    // allow: [],  // 未指定 = 全許可。指定するとホワイトリストモード
    deny: [
      'move_to_trash',  // 非可逆: 30日後に永久削除
    ]
  }
};
```

### ルール

| allow | deny | 結果 |
|-------|------|------|
| 未指定 | 未指定 | 全許可（後方互換） |
| 未指定 | `['move_to_trash']` | move_to_trash 以外は全許可 |
| `['search','get_thread']` | 未指定 | 明示したものだけ許可 |
| `['search']` | `['search']` | deny が優先 → 拒否 |

- **deny が優先**（Claude Code と同じ）
- allow を書き始めたらホワイトリストモード（明示したものだけ許可）
- permissions キー自体が未指定 = 全許可（既存インストールへの後方互換）

### デフォルト設定

```javascript
permissions: {
  deny: [
    'move_to_trash',  // 非可逆: 30日後に永久削除
  ]
}
```

今後、破壊的かつ非可逆な機能を追加する際は deny のデフォルトに含める方針。

### 2. gas-template/utils/permissions.js（新規）

```javascript
/**
 * Check if an action is allowed by CONFIG.permissions
 *
 * Follows Claude Code allow/deny pattern:
 * - deny takes priority over allow
 * - If allow is specified, only listed actions are permitted (whitelist)
 * - If neither is specified, all actions are allowed (backward compat)
 *
 * @param {string} action - Action name to check
 * @returns {boolean} Whether the action is allowed
 */
function isActionAllowed(action) {
  if (!CONFIG.permissions) return true;

  var deny = CONFIG.permissions.deny;
  var allow = CONFIG.permissions.allow;

  // deny takes priority
  if (deny && deny.indexOf(action) !== -1) return false;

  // allow specified = whitelist mode
  if (allow && allow.length > 0) {
    return allow.indexOf(action) !== -1;
  }

  return true;
}
```

### 3. gas-template/main.js

doGet と doPost の両方で、アクション実行前にチェックを追加:

```javascript
function doGet(e) {
  try {
    const action = e.parameter.action;

    if (!action) {
      return successResponse({ status: 'ok', message: 'Gmail Skill is running', version: '1.0.0' });

    // Permission check

      return errorResponse(
        `Action "${action}" is denied by permissions config. ` +

      );
    }

    switch (action) {
      // ... 既存のルーティング
```

## ccskill シリーズ共通仕様

この permissions パターンは ccskill シリーズの共通仕様とする:

- `CONFIG.permissions` のキー名・allow/deny ルールは全 ccskill で統一
- ドメイン固有の設定（SPREADSHEETS 等）はそれぞれ自由に追加
- 破壊的かつ非可逆な操作はデフォルトで deny に含める
