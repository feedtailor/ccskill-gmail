## 概要

`ccskill-gmail api ...` サブコマンドを新設し、プロジェクトにコピーされた `.ccskill-gmail/api` と同じ `lib/api` を直接呼べるようにする。既存の挙動は一切変えない (install 済みプロジェクトでの動作は従来どおり)。全体方針は #121 を参照。

## 実装内容

### 0. 要検証事項の裏付け (実装前に必ず実施)

claude-code-guide エージェントで以下 3 点を確認し、結果を本 issue に記録する:

1. プロジェクトスキルとユーザースキルが同名のときの優先・共存挙動
2. permissions allow ルールにマッチした Bash コマンドと sandbox の関係 (home への書込が通る条件)
3. skill frontmatter `allowed-tools` での `Bash(ccskill-gmail api:*)` パターンの有効性

検証結果が #121 のアーキテクチャ前提を崩す場合は、実装前に #121 の見直しに戻る。

#### 検証結果 (2026-06-10、claude-code-guide による公式 docs 調査)

| # | 項目 | 結果 |
|---|---|---|
| 1 | 同名スキルの優先 | **確認済み・仮説と逆**。"enterprise overrides personal, and personal overrides project" — ユーザースキルがプロジェクトスキルを上書き (シャドーイング、両方は一覧に出ない)。根拠: code.claude.com/docs/en/skills.md "Where skills live" |
| 2 | allow ルールと sandbox | **確認済み**。permission ルールと sandbox は独立。allow は確認プロンプトのスキップのみで、sandbox の filesystem/network 制限は適用されたまま。home への書込には sandbox 設定 (`sandbox.filesystem.allowWrite`) が別途必要。根拠: code.claude.com/docs/en/permissions.md, sandboxing.md |
| 3 | frontmatter allowed-tools | **確認済み**。`allowed-tools: Bash(cmd *) ...` (スペース区切り複数) は有効。スキル実行中の確認プロンプトをスキップする許可リストで、ツールの制限ではない。sandbox 境界は変えない。根拠: code.claude.com/docs/en/skills.md |

**アーキテクチャへの影響判断**: 3 点とも #121 の設計を崩さない。(1) により「ユーザースキル登録者はレガシープロジェクトでも新表記が適用される」ため、本 issue の cwd フォールバックが後方互換の生命線に昇格 (#121 修正済み)。(2) により home への履歴書込・トークン書き戻しの縮退パスが「フォールバック」ではなく通常経路となる (#123 の auth.sh 改修、#125 の doctor 案内が必須要件に)。

### 1. ディスパッチャへの `api` サブコマンド追加

`ccskill-gmail` (74-125 行の case 文) に追加:

```bash
api)
    exec "$CCSKILL_GMAIL_DIR/lib/api" "$@"
    ;;
```

help 表示にも追記する。

### 2. lib/api の解決順拡張

現状 `_api_init` (lib/api:28-99) は `$SCRIPT_DIR/.ccskill-metadata.json` のみ参照する。グローバル呼び出し時 (SCRIPT_DIR = マスター lib/) はメタデータが無いため、解決順を拡張:

```
1. $SCRIPT_DIR/.ccskill-metadata.json   (従来 = プロジェクトコピーの api 経由。最優先で据え置き)
2. $PWD/.ccskill-gmail/.ccskill-metadata.json   (グローバル呼び出し + install 済みプロジェクト)
```

この Phase では cwd のメタデータ読みまで。accounts.json 参照は #123。
