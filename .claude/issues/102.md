## 概要

ccskill-gmail に「レシピ (recipes)」という軽量な仕組みと、それを生成支援する「recipe-creator」を内蔵する構想。本 issue は全体方針と設計決定を記録する meta issue。実装は #103-#106 に分割する。

## 背景

ccskill-gmail は Gmail の汎用 API 集として成熟しつつあるが、以下の課題がある:

- 日々の業務は API の組み合わせで成立するが、組み合わせパターンをユーザーが毎回プロンプトで組み立てている
- Gmail settings (フィルタ等) への拡張は permission 追加を要し、design principle (no send / no permanent delete) との兼ね合いで慎重な設計が必要
- アドバイザリーサービス (feedtailor) への送客において "業務適用の具体例" が訴求材料として不足

これに対し、プラグイン機構のような大仕掛けは時期尚早という結論。permission を追加しない軽量な「レシピ」を導入し、業務パターンをパッケージ化する方針とする。さらに、ユーザー自身の利用履歴からレシピ化候補を提案する recipe-creator を内蔵し、「使えば使うほど自分用に育つ」体験を提供する。

## 核となる定義

| 概念 | 定義 |
|---|---|
| Skill (ccskill-gmail) | Gmail 操作を汎用的に行う「道具と作法」。API と行動ルールの束 |
| Recipe | Gmail 操作を特定業務向けに型化した「業務パターン・パッケージ」 |
| recipe-creator | ユーザーの audit log / 会話履歴 (opt-in) を元にレシピ候補を提案・生成する内蔵機能 |

Skill と Recipe は同じ抽象化パターンを一段下に適用した fractal 構造。ccskill-gmail という 1 つのスキルの中の機能として、recipes と recipe-creator が従属する (独立スキル化しない)。

## 設計決定

ユーザーとの議論で合意済み:

1. **permission 追加しない範囲で成立** — 現行 API だけで業務パターンを表現
2. **同梱構造 (独立スキル化しない)** — recipe-creator はドメイン依存のため ccskill-gmail に内蔵
3. **SKILL.md は浅く** — 導線のみ記載、詳細は recipe-creator.md に
4. **起動トリガー**: ユーザーの明示的呼び出しのみ
5. **会話履歴アクセス**: 前提としない。オプトイン
6. **発動方式**: 自然言語呼び出し + `/gmail-<recipe>` スラッシュコマンド自動登録のハイブリッド (A+C)
7. **命名**: `recipe-creator-templates/` (用途明確で混同を避ける)
8. **progressive context injection**: SKILL.md は軽く、深い情報は必要時のみロード
9. **将来の独立化余地**: ディレクトリ単位で切り出せる構造を維持

## ディレクトリ構造

```
.claude/skills/ccskill-gmail/
├── SKILL.md                       # 浅: recipes / recipe-creator への導線を末尾に追加
├── examples.md                    # 既存
├── troubleshooting.md             # 既存
├── reference/                     # 既存 (本体 reference)
├── recipes/                       # 中: レシピ集
│   ├── README.md                  #   概念・一覧・使い方
│   └── <recipe-name>/             #   Pain 単位のディレクトリ
│       ├── README.md              #     何を解決するか
│       ├── prompt.md              #     Claude に渡す定型プロンプト
│       ├── config-sample.js       #     (任意) 設定サンプル
│       ├── automation.sh          #     (任意) shell 自動化
│       └── example-output.md      #     期待結果サンプル
├── recipe-creator.md              # 深: recipe-creator の行動ルール (1ファイル)
└── recipe-creator-templates/      # 生成時のテンプレート
    ├── README.md.tmpl
    ├── prompt.md.tmpl
    └── example-output.md.tmpl
```

## アドバイザリー連携

recipes は feedtailor アドバイザリーサービスとの接続点:

- 汎用レシピを OSS 公開 → 認知と送客の道具
- 顧客固有の業務パターンを「カスタムレシピ」としてアドバイザリー内で作成
- 汎用化可能なものは OSS 還流 → ccskill-gmail の説得力を継続的に育てる

recipe-creator があることで、月次セッションの「あなたの業務をレシピ化します」という具体的メニューが成立する。

## スコープ外

- プラグイン機構 (GAS scope 拡張を伴う拡張) — 時期尚早。recipe 定着後に再検討
- ccskill-core 共通フレームワーク化 — ccskill-spreadsheet 着手後に検討
- 3rd party 製レシピ受け入れ — 当面は公式のみ
- ユーザー生成レシピと配布レシピの厳密な分離 — 当面は `recipes/` 混在で OK。必要なら `recipes/official/` と `recipes/custom/` に分ける余地を残す
