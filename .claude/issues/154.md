## 概要
ccskill-gmail の実機テスト中に、Claude Code のサンドボックス環境に起因する症状と、GAS側の一時的な不調による症状を確認した。いずれも `troubleshooting.md`（ユーザー向けドキュメント）には記載がなく、自分用の `CLAUDE.md` や個人メモリにしか記録していなかった。ccskill-gmail の利用者は原則として全員 Claude Code 経由であるため、両症状ともユーザー向けドキュメントに追記する価値がある。


## 出典
本セッションでの実機調査（ccskill-gmailプロジェクト、2026-08-03）。ユーザーからの指摘により着手。


## 詳細

### 症状1: サンドボックスによる gas_token リフレッシュ阻害
`ccskill-gmail api get ...` を Claude Code のサンドボックス化された Bash ツールから呼び出すと、
以下のエラーが出ることがある。

```
ERROR: Token refresh failed: . Run 'ccskill-gmail account add'.
```

`Token refresh failed:` の後のエラー詳細が空文字列になっているのが特徴。これは
`lib/auth.sh` の `gas_token()` が `oauth2.googleapis.com` へリフレッシュリクエストを送る際、
Claude Code のサンドボックスがネットワークアクセスを許可していてもなお（許可ホスト一覧に
含まれる場合でも）稀にブロックし、curl が空レスポンスを返すことに起因する。認証情報自体は
壊れておらず、再認証（`clasp login` や `account add`）は不要。サンドボックスを無効化して
同じコマンドを再実行するだけで解消する。

### 症状2: GAS側の一時的な「ページが見つかりません」応答
`ccskill-gmail api get/post` の呼び出しの一部で、期待するJSONの代わりに Google ドライブ形式の
「現在、ファイルを開くことができません。アドレスを確認して、もう一度試してください。」という
HTMLが返ることがある（`troubleshooting.md` に既存の「HTML returned (login page)」症状とは別物で、
ログインページではない）。本セッションで7回のAPI呼び出し中3回発生し、いずれもサンドボックス無効化
状態でも発生した（つまりサンドボックスとは無関係）。再試行すると必ず成功しており、GAS側の一時的な
インフラ不調と考えられる。認証・デプロイ自体に問題はない。

なお本issueはドキュメント追記のみを扱う。同じ調査から派生したコード改善（`lib/api.sh` への
自動リトライ実装）は [[155]] で別途扱う。
