## 概要

グローバル化(#121-126)で「1 インストール・ユーザレベルで複数 Gmail を横断利用できる central 型」になった。この優位性が README で十分に前面に出ていない。マルチアカウント対応を最大の差別化点として再構成し、インストール前に `ccskill-gmail` のコマンド例を出さない構成へ整える。あわせて技術情報を別ドキュメントへ分離する。README.md / README.ja.md の両方に対称適用する。

## 点検結果（変更不要と確認した箇所）

将来のセッションが再検証しなくて済むよう記録する。

- Installation「git clone」/ Update「git clone」: 現在の central 正規フロー(setup → account add → skill install、git pull → update-all)と整合。変更不要。
- 「複数アカウント利用 / Using multiple accounts」: `account add` / `list` / `default`、`--account` / `bind` / default の優先順位、`whoami` が実装と一致。変更不要。
- 「技術情報 / Technical details」の本文: 「アカウントごとに 1 デプロイ・全ディレクトリ共有」など central 型と整合。OAuth 権限表も無関係。内容変更は不要（分離のみ）。

## 実装内容

1. 機能比較表: 「マルチアカウント対応」を ccskill-gmail 列のみ ◎ にし、行を「ラベルの付与・削除」の直下へ配置する。凡例や「1 インストールで横断利用」等の補足は付けない（素のラベルのまま。レビューでの確定事項）。
2. 特徴的な機能: 「複数アカウント対応」をセクション先頭へ移動。インストール前に出ていた `ccskill-gmail` コマンド例 2 ブロックを削除し、魅力を語る散文に置き換える。
3. 具体的な使用例: 複数アカウントを横断する例を先頭に新設する。
4. 独自スクリプトの開発: 3 例を 2 つ目（請求書 PDF の一括ダウンロード）のみに絞る。
5. Update「zip 配布」: 「extract → account update」を central 型に修正する（symlink が使えない環境向けに `skill install --copy`）。git clone 側と体裁を揃え、展開コマンド `cd ~/projects && unzip -o ...` を明示する。
6. 「すでに使っている方へ / 旧 ccskill-gmail をご利用の方へ」: 冗長な小節を migrate 中心の簡潔な説明に圧縮する（#130 で追加された節）。
7. 技術情報の分離: 「Technical details / 技術情報」セクションを `docs/technical-details.md` / `docs/technical-details.ja.md` へ移し、README には短い要約とリンクを残す。
8. コマンド一覧の分離（スコープ追加）: 全コマンドの一覧を `docs/commands.md` / `docs/commands.ja.md` へ切り出し、README からはポインタ 1 行のみにする。
9. セクション順の整理（スコープ追加）: 「複数アカウントの登録方法」をインストール直後へ、「旧 ccskill-gmail をご利用の方へ」をインストール群の最後（更新の手前）へ移す。新規ユーザーの導線→既存ユーザーの移行→運用、の並びにする。「複数アカウントの登録方法」は #138 の新フロー（認証後にラベルを尋ねる）に合わせて記述する。
