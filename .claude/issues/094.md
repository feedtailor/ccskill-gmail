## 概要

`triage.md` には「要返信メール」分類の本命ロジック（reply-now / waiting / draft-needed / fyi / archive、最終メッセージ送信者による判定）が定義されているが、**SKILL.md から triage.md への参照が一切存在しない**。結果、スキル呼び出し経由で入ってきた Claude は triage.md の存在を認識できず、自己流で検索クエリを組み立てて誤った結果を返してしまう。

## 再現した事象

`/loop 要返信メールをpickup` の実行時に、Claude が以下の検索クエリを組み立てて **0件**と誤報告した:

```
newer_than:1d is:unread category:primary -from:noreply ...
```

実際には既読状態の未返信メール（oka@alpha-create.ne.jp、スレッド messageCount:16）が存在していた。triage.md の「waiting = Last message in thread is from user」ルールを参照できていれば「最終メッセージが相手から = reply-now 候補」という判定ロジックで正しく拾えた。

## 根本原因

1. **Related Documentation セクションに triage.md が列挙されていない**
   - SKILL.md 末尾の Related Documentation は `reference/` / `troubleshooting.md` / `examples.md` のみ
   - triage.md は孤児（orphaned）状態
2. **Email Review Guidelines セクション（SKILL.md:371）から triage.md へのリンクがない**
   - 該当セクションは「Filter out automated senders」「structured summary」の2点の抽象ルールしか書かれておらず、具体ロジックを持つ triage.md を参照していない
3. **triage.md 側から SKILL.md への逆リンクは存在する**（"Integration with Email Review Guidelines"）が、**順方向のリンクがない**ため、Claude が triage.md に辿り着けない

## 改善内容

### 1. SKILL.md の Related Documentation に triage.md を追加

```markdown
## Related Documentation

- [API Reference](reference/) - Detailed specifications for all APIs
- [Email Triage Workflow](triage.md) - Classification rules for "emails that need a reply" (reply-now / waiting / draft-needed / fyi / archive)
- [Troubleshooting](troubleshooting.md) - Common issues and solutions
- [Workflow Examples](examples.md) - Practical usage examples
```

### 2. Email Review Guidelines セクションから triage.md への明示リンク

SKILL.md:371 の Email Review Guidelines セクションに以下の一文を追加:

```markdown
For the full classification workflow (reply-now / waiting / draft-needed / fyi / archive), see [triage.md](triage.md). Always consult this document when the user asks "any emails I should reply to?" or similar.
```

### 3. triage.md 冒頭に "When to use this" セクションを新設

Claude が「要返信 / 未返信 / reply needed / check my emails」等のキーワードを検知した時点で triage.md を開くように、トリガー語彙を明記する:

```markdown
## When to use this document

Read this document BEFORE constructing any search query if the user's request matches any of:
- "要返信" / "未返信" / "返信漏れ" / "返信すべきメール"
- "reply needed" / "emails I should reply to" / "pending replies"
- "check my emails" / "triage my inbox" / "scan inbox"

Do NOT improvise a search query based on `is:unread` — the classification below is
independent of read state.
```

2026-04-14 の運用事故。`/loop 要返信メールをpickup` で `is:unread` を付けてしまい、既読状態の未返信メールを見落とした。原因調査で triage.md が SKILL.md から到達不可能な状態と判明。
