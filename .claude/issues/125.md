## 概要

既存ユーザーの正式移行経路と、ディレクトリ固定の安全機能を提供する。全体方針は #121 を参照。

## 実装内容

1. **`commands/bind.sh` (新規)** — `ccskill-gmail bind <email|label> [DIR]`: cwd (または DIR) に `.ccskill-gmail/binding.json` を書くだけの軽量バインド (GAS 作成なし、数秒)。プロジェクト permission の追記は opt-in 提示。`unbind` も対で用意
2. **`lib/api` のバインド解決** — 解決チェーンの「cwd のプロジェクトバインド」に binding.json (新形式) を追加 (旧 .ccskill-metadata.json と並ぶレガシー/新形式の両対応)
3. **`commands/migrate.sh` (新規)** — `.registry.json` の installations を email でグルーピング → 各 email につき既存デプロイの 1 つをアカウント代表として accounts.json に登録 (**再認可不要**) → 各プロジェクトに binding.json を書く (旧メタデータは残置) → 余った重複 GAS デプロイは一覧表示して手動削除を案内 (自動削除しない)
4. **履歴の中央化** — `lib/history.sh`: 記録先を `~/.ccskill-gmail/history/<email>/audit.jsonl` に変更、レコードに `account` フィールド追加。レガシープロジェクト (バインド済み) では従来位置への記録も維持 (`CCSKILL_HISTORY_DIR` 上書きは存続)。sandbox 内で書込不可なら無言スキップ (既存縮退設計 :38-47 踏襲)
5. **`commands/history.sh` の対応** — アカウント横断表示・`--account` フィルタ
6. **`doctor` 拡充** — PATH / accounts.json / binding / sandbox 書込可否 / ユーザースキル登録状態の診断

## 完了条件

- [ ] `bind` したディレクトリでは `--account` 指名がない限り必ずバインド先アカウントが使われる
- [ ] 既存マルチプロジェクト環境で `migrate` 実行 → 再認可なしで accounts.json 登録 + 各プロジェクトの binding 完了、従来の `.ccskill-gmail/api` も動き続ける
- [ ] グローバル利用時の操作が `~/.ccskill-gmail/history/<email>/` に記録され、`ccskill-gmail history` でアカウント横断表示できる
- [ ] sandbox 内実行で履歴書込が失敗しても API 操作自体は成功する
