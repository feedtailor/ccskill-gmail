## 概要

`.ccskill-gmail/api` スクリプトの全サブコマンド呼び出しをローカル JSONL ファイルに自動記録する仕組みを追加する。
エージェント AI が自らの操作履歴を振り返り、ユーザーが「AI が何をしたか」を確認するための機構。

## 背景

セキュリティレビューで「監査ログがない」という指摘があった。エンタープライズ的な監査ログは
個人ツールとして過剰だが、AI エージェントが自分の作業を振り返る用途、およびユーザーが
AI の操作を事後確認する用途では価値がある。

ccskill-spreadsheet では #058-067 で Audit Log 機能が詳細に設計されている（未着手）。
Gmail 版は spreadsheet と異なり before/after やビジュアル差分は不要で、
action + params + timestamp + result のシンプルな記録で十分。

## 前提: #051 後のアーキテクチャ

#051 で `source .ccskill-gmail/api.sh && ccskill-get` パターンは廃止され、
`.ccskill-gmail/api get|post|download|save-html|save-pdf` の単体実行形式に移行済み。

全リクエストが `lib/api` のメインディスパッチャを通るため、
フックは **1箇所（case 分岐の前後）** に入れるだけで全サブコマンドをカバーできる。

## 設計方針

### ccskill-spreadsheet との関係

spreadsheet 側の設計（#058-067）を参考にするが、以下の点で異なる：

| 観点 | spreadsheet | gmail |
|------|------------|-------|
| write の破壊性 | 高い（セル上書き） | 低い（下書き作成、ラベル変更） |
| before/after | 必要（セルの旧値→新値） | 不要 |
| ビジュアル差分 | あり（シートハイライト） | なし |
| ログの主な用途 | 誤操作の復元 | AI の作業振り返り・ユーザーの事後確認 |

### フックポイント

`lib/api` のメインディスパッチャ全体（unknown subcommand を含む `*` 分岐も対象）を
ラップする形でフックを挿入する。

```bash
# メインディスパッチャ内（イメージ）
_api_init || exit 1

# ログ機構の読み込み（存在する場合のみ）
if [ -f "$SCRIPT_DIR/history.sh" ]; then
    source "$SCRIPT_DIR/history.sh"
fi

# 呼び出し前: リクエスト情報を記録用に保持
_LOG_SUBCOMMAND="$SUBCOMMAND"
_LOG_ARGS=("$@")

case "$SUBCOMMAND" in
    get)       cmd_get "$@" ;;
    post)      cmd_post "$@" ;;
    download)  cmd_download "$@" ;;
    save-html) cmd_save_html "$@" ;;
    save-pdf)  cmd_save_pdf "$@" ;;
    *)
        echo "{\"ok\":false,\"error\":\"Unknown subcommand: ${SUBCOMMAND}...\"}"
        # unknown subcommand もログに記録（プロンプトインジェクション検知）
        if type _ccskill_history_record &>/dev/null; then
            _ccskill_history_record "$_LOG_SUBCOMMAND" 1 "unknown" "${_LOG_ARGS[@]}"
        fi
        exit 1
        ;;
esac
_LOG_EXIT_CODE=$?

# 呼び出し後: ログ記録（history.sh が読み込まれている場合のみ）
if type _ccskill_history_record &>/dev/null; then
    _ccskill_history_record "$_LOG_SUBCOMMAND" "$_LOG_EXIT_CODE" "${_LOG_ARGS[@]}"
fi
```

旧設計との違い:
- `ccskill-get` / `ccskill-post` 関数内のフックは不要（関数自体が廃止済み）
- `history.sh` の有無で条件分岐するのはスクリプト内部の制御なので透過的
- 全サブコマンド + unknown subcommand が自動的にカバーされる

### ストレージ

```
.ccskill-gmail/history/audit.jsonl      # 現行ログ

```

### パラメータ記録方針

パラメータを3分類し、記録方針を明確に分ける:

| カテゴリ | 例 | 記録方法 | 理由 |
|---------|-----|---------|------|
| **識別パラメータ** | threadId, messageId, draftId, label, attachmentIndex | **値を記録** | PII ではない。トレーサビリティに必須 |
| **内容パラメータ** | body, subject, to, cc, bcc, htmlBody, query | **キー名のみ** | PII を含みうる（`query="from:秘密の連絡先"` 等） |
| **制御パラメータ** | maxResults, includeHeaders, replyAll, skipSelf | **値を記録** | 機密性なし。動作理解に有用 |

識別パラメータの完全リスト:
- `threadId`, `messageId`, `draftId` — メール/スレッド/下書きの識別子
- `label` — ラベル名（ユーザー作成のラベル名は業務内容を推測可能だが、ログの有用性を優先）
- `attachmentIndex` — 添付ファイルのインデックス

内容パラメータの完全リスト:
- `to`, `cc`, `bcc` — メールアドレス
- `subject`, `body`, `htmlBody` — メール件名・本文
- `query` — 検索クエリ（`from:秘密の連絡先` 等を含みうる）
- `attachments` — 添付ファイルデータ

### JSONL スキーマ

```json
{
  "id": "20260307T143022_a1b2c3",
  "timestamp": "2026-03-07T14:30:22+0900",
  "project": "/Users/oishi/projects/ftgmail",
  "subcommand": "post",
  "action": "create_reply_draft",
  "identifiers": { "threadId": "19bf7f25b96ab637" },
  "contentKeys": ["body"],
  "controls": { "replyAll": "true", "skipSelf": "true" },
  "response_ok": true,
  "error": null,
  "duration_ms": 1234
}
```

各フィールドの説明:

| フィールド | 説明 | 取得方法 |
|-----------|------|---------|
| id | 一意 ID | `_ccskill_history_gen_id` で生成 |
| timestamp | ISO 8601 タイムスタンプ | `date` コマンド |
| project | 呼び出し元プロジェクトディレクトリ | `$PWD` |
| subcommand | サブコマンド名 | `get`, `post`, `download`, `save-html`, `save-pdf`, または unknown |
| action | GAS API のアクション名 | get: 引数から `action=` を抽出、post: JSON から `.action` を抽出 |
| identifiers | 識別パラメータ（値あり） | パラメータ分類に基づき抽出 |
| contentKeys | 内容パラメータのキー名一覧 | パラメータ分類に基づき抽出 |
| controls | 制御パラメータ（値あり） | パラメータ分類に基づき抽出 |
| response_ok | GAS レスポンスの `.ok` フィールド | stdout をキャプチャして `jq -e '.ok'` で判定 |
| error | GAS レスポンスのエラーメッセージ | `response_ok` が false の場合に `.error` を抽出 |
| duration_ms | 実行時間（ミリ秒） | 開始時刻と終了時刻の差分 |

### GAS レスポンスのキャプチャ方法

`response_ok` と `error` を記録するために、サブコマンドの stdout をキャプチャする必要がある。

```bash
# stdout をキャプチャしつつ、そのまま出力する
_LOG_RESPONSE=$(cmd_get "$@" | tee /dev/stderr 2>&1)
# ※ 実装時に最適なキャプチャ方法を選定（tee + fd リダイレクト等）
```

### ログの肥大化防止

- **行数上限**: 1000行
- **ローテーション**: 超過時に `audit.jsonl` → `audit.jsonl.1` にリネーム後、新規ファイルで継続
  - 1世代のみ保持（実質 ~2000行 = 数週間分）
  - `audit.jsonl.1` は次回ローテーション時に上書き
- **切り詰め実装**: temp ファイル + `mv`（atomic rename）を使用。直接リダイレクトは race condition の原因になるため禁止
- **手動クリア**: `ccskill-gmail history clear --yes`（`--yes` 必須）

### ログファイルのセキュリティ

- ディレクトリ: `chmod 700 .ccskill-gmail/history/`
- ファイル: `chmod 600 .ccskill-gmail/history/audit.jsonl`
- `_ccskill_history_record` がファイル新規作成時に上記パーミッションを設定

### opt-out 機構

`CCSKILL_GMAIL_HISTORY=off` 環境変数でログ記録を無効化できる。
`.env` または `.ccskill-gmail/config` に設定可能。

```bash
# history.sh 冒頭
if [ "${CCSKILL_GMAIL_HISTORY:-}" = "off" ]; then
    # _ccskill_history_record を空関数として定義
    _ccskill_history_record() { :; }
    return 0
fi
```

### 共通コア（lib/history.sh）

spreadsheet #059 の設計を流用可能な関数：

- `_ccskill_history_gen_id` — `YYYYMMDDTHHMMSS_XXXXXX` 形式の一意 ID 生成
- `_ccskill_history_record` — JSONL ファイルに1行追記（パラメータ分類・レスポンス解析を含む）
- `_ccskill_history_list` — 最新 N 件のログを表示（human-readable / JSON）
- `_ccskill_history_clear` — ログファイルを空にする（`--yes` 必須）
- `_ccskill_history_rotate` — 行数チェック + ローテーション

将来的に ccskill-spreadsheet と共通モジュールとして切り出す可能性がある。
現時点では ccskill-gmail 内に独立して実装する。

## history サブコマンド

`ccskill-gmail history` として以下を提供：

```bash
# 最新 20 件のログを人間可読形式で表示（デフォルト）
ccskill-gmail history
# 出力例:
#   2026-03-17 14:30 — search (GET) → OK, 1.2s
#   2026-03-17 14:31 — create_reply_draft (POST) thread:19bf... → OK, 0.8s
#   2026-03-17 14:32 — archive (POST) thread:19bf... → OK, 0.5s

# JSON 形式で出力（Claude や jq での処理用）
ccskill-gmail history list --json

# 最新 N 件
ccskill-gmail history list 50

# フィルター
ccskill-gmail history list --action create_draft
ccskill-gmail history list --since 2026-03-17
ccskill-gmail history list --errors

# ログをクリア（--yes 必須）
ccskill-gmail history clear --yes
```

### 出力形式

**デフォルト: human-readable**

ユーザー（非エンジニア含む）が一目で理解できる形式:
```
2026-03-17 14:30 — search (GET) → OK, 1.2s
2026-03-17 14:31 — get_thread (GET) thread:19bf7f25 → OK, 0.8s
2026-03-17 14:32 — create_reply_draft (POST) thread:19bf7f25 → OK, 2.1s
2026-03-17 14:33 — mark_read (POST) thread:19bf7f25 → OK, 0.5s
2026-03-17 14:34 — archive (POST) thread:19bf7f25 → OK, 0.4s
2026-03-17 15:01 — search (GET) → ERROR: Timeout, 60.0s
```

**`--json`: JSONL 出力**

Claude やスクリプトでの処理用。`jq` でのフィルタリングに適する。

### プライバシーノート

SKILL.md またはヘルプ出力に以下を記載:

- **記録される情報**: アクション名、識別ID（threadId等）、成功/失敗、実行時間
- **記録されない情報**: メール本文、宛先、件名、検索クエリの内容
- **保存場所**: `.ccskill-gmail/history/audit.jsonl`（ローカルのみ、git 対象外）
- **無効化**: `CCSKILL_GMAIL_HISTORY=off` で記録を停止可能
