## タスク概要

`gas-template/appsscript.json` を更新し、セキュリティモデルを `ANYONE` → `MYSELF` に変更。
同時に不要な OAuth スコープ `script.external_request` を削除する。

## 背景

- 現状: `appsscript.json` に `webapp` セクションがなく、デプロイ時に手動で "Anyone" を選択
- 問題: URL 知っていれば誰でも Gmail にアクセス可能
- 解決: `webapp.access: "MYSELF"` を明示 + OAuth Bearer トークン認証

review_20260206.md の Issue 1（HIGH）と Issue 3（LOW）に対応。

## 変更ファイル

### `gas-template/appsscript.json`

```json
{
  "timeZone": "Asia/Tokyo",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "access": "MYSELF",
    "executeAs": "USER_DEPLOYING"
  },
  "oauthScopes": [
    "https://www.googleapis.com/auth/gmail.readonly",
    "https://www.googleapis.com/auth/gmail.compose",
    "https://www.googleapis.com/auth/gmail.modify"
  ]
}
```

### 変更点

1. **`webapp` セクション追加**:
   ```json
   "webapp": {
     "access": "MYSELF",
     "executeAs": "USER_DEPLOYING"
   }
   ```
   - `access: "MYSELF"` → デプロイしたユーザー本人のみアクセス可
   - `executeAs: "USER_DEPLOYING"` → デプロイしたユーザーの権限で実行

2. **不要スコープ削除**:
   ```diff
   - "https://www.googleapis.com/auth/script.external_request"
   ```
   - このスコープは `UrlFetchApp` 用だが、Gmail Skill では使用していない
   - 最小権限の原則に基づき削除

## 注意事項

- 既存インストール先は手動でデプロイし直す必要がある（マイグレーション手順を update.sh に含める）
- `MYSELF` デプロイでは `clasp login` で取得したトークンが Bearer ヘッダーとして必要
- GAS エディタで手動デプロイする場合も「自分のみ」を選択する必要がある

## テスト方法

```bash
# 1. appsscript.json の構文チェック
cat gas-template/appsscript.json | jq .  # 有効な JSON か確認

# 2. clasp push して GAS プロジェクトに反映
push_gas ".ccskill-gmail" "$CCSKILL_GMAIL_DIR"

# 3. deploy して MYSELF アクセスを確認
deploy_gas ".ccskill-gmail" "" "Security model test"

# 4. 認証なしアクセスが拒否されることを確認
curl -sL "$GMAIL_ENDPOINT"  # → エラー or HTML（アクセス拒否）

# 5. Bearer トークン付きアクセスが成功することを確認
curl -sL -H "Authorization: Bearer $(gas_token)" "$GMAIL_ENDPOINT"
# → {"ok":true,"data":{"status":"ok",...}}
```
