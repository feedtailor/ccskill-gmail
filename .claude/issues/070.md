## 概要

SSH 経由やヘッドレス環境での install 時に、ブラウザが開けず認証フローが詰まる問題を解決する。

## 背景

別マシンに SSH で接続して `ccskill-gmail install` を実行した際、以下の問題が発生した:

1. `open` コマンドでブラウザが開けない（SSH 先にはデスクトップがない）
2. OAuth 認証 URL が表示されないため、ユーザーが手動でブラウザに貼る URL がわからない
3. Enter を押すタイミングが不明確
4. Apps Script API 未有効化時のエラーメッセージが不正確

## 改善内容

### 1. OAuth URL の併記

「Press Enter to open the authorization page...」の箇所で、Web App の exec URL を常に表示する:

```
If the browser doesn't open automatically (e.g. SSH environment),
open this URL manually:
  https://script.google.com/macros/s/DEPLOY_ID/exec
```

### 2. Enter タイミングの案内

```
Press Enter after completing the authorization...
```

を以下のように改善:

```
After the browser shows {"ok":true,...}, press Enter to continue...
```

### 3. Apps Script API 未有効化のエラーメッセージ改善

現在:
```
This usually means your Google credentials have expired.
Run the following to re-authenticate:
  ccskill-gmail setup
```

改善後:
```
The Apps Script API is not enabled for this account.
Enable it at: https://script.google.com/home/usersettings
Then re-run: ccskill-gmail install
```

### 4. OAuth 失敗時のフォローアップ改善（テストで判明）

実機テスト（2026-04-02）で以下の問題が判明:

- マルチアカウント環境でリダイレクトループが発生した際、回復手順が不明確
- 「プライベートウィンドウで開け」だけでは不十分。正しいアカウントでログイン → クリーンな exec URL を開く、という手順が必要
- ブラウザのエラーページに表示される URL は再帰エンコードで壊れているため使用不可

対応:
- install.sh の OAuth セクションにトラブルシューティングを追記（プライベートウィンドウ + accounts.google.com でログイン → URL 貼り付けの手順）
- リトライ時のメッセージに「正しいアカウントでログイン」ステップを追加
- 3回失敗後の回復手順を具体化（accounts.google.com の URL を明記）
- README トラブルシューティングに「壊れた URL を使わない」注意を追記
- install.sh の「OAuth Authorization」表記を「Google Authorization」に統一

### 5. Multi-account セクションの `clasp login` 手順削除（テストで判明）

実機テスト（2026-04-02）で、`clasp --user <name> login` を事前に実行しなくても `ccskill-gmail install --user <name>` が動作することが判明。install.sh 内のログインチェックが未ログイン時に自動で `clasp login` を実行するため。

対応:
- README の Multi-account セクションから `clasp --user work login` の事前ステップを削除
- #074 のエラーメッセージから `Login first with: clasp --user <name> login` を削除
