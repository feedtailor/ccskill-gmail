## 概要

`create_draft` の `to` フィールドは現在必須。空文字列を渡すと `Missing required parameter: to` エラーになるため、宛先が未確定な状態の下書きを作れない。

Gmail のブラウザ UI / アプリでは宛先なし下書きを普通に作成・保存できるが、スキル経由では不可能。AI が宛先未確定の下書き作成を依頼された場合にワークアラウンドを強いられる。

## 背景

GmailApp.createDraft は `recipient` 引数が必須のため、空文字列を渡すとエラーになる。一方、Gmail REST API（Advanced Services の `Gmail.Users.Drafts.create`）は `to` を任意とした MIME メッセージを受け付けるため、技術的には宛先なし下書きの作成が可能。

## 実装内容

1. **`to` をオプション化** — `to` が省略または空文字列の場合、GmailApp を使わず Gmail REST API 経由（`Gmail.Users.Drafts.create`）で下書きを作成する
2. **SKILL.md / `reference/draft.md` の更新** — `to` がオプションになった旨と、宛先なし下書きの使い方を追記

## 完了条件

- [ ] `to` を省略した `create_draft` が成功し、Gmail の下書き一覧に宛先なし下書きが作成される
- [ ] `to` を指定した場合の既存動作が変わらない
- [ ] `reference/draft.md` の `to` パラメータが `Required: ✓` から任意に更新されている

## 却下判断 (2026-06-16)

**却下。実装しない。**

`to` なし下書きの作成は技術的に追加の権限/サービスを必須とすることが判明したため、プロジェクト方針と相容れず却下した。

- `GmailApp.createDraft` は `to` を必須引数とするため、バリデーションを緩める（`requireParam` を外す）だけでは作れない。空文字を渡しても GmailApp が拒否する。
- 回避手段はいずれも追加の権限/サービスを要する:
  - Advanced Gmail Service（`Gmail.Users.Drafts.create`）→ Advanced Service の有効化が必要
  - `UrlFetchApp` で Gmail REST API 直叩き → `script.external_request` スコープの追加が必要
- **プロジェクト方針（2026-06-16 ユーザー判断）**: 「余計な権限を求めることを前提とする実装は許可しない。Advanced Service の利用も認めない」。本 issue はこの方針に抵触するため却下。
- **代替運用**: 宛先未確定のユースケースは #127 で整備した name-addr プレースホルダ（`"\"岸田様\" <placeholder@example.com>"`）で実用上回避できる。実害はない。

> 起票（2026-06-13）時点で権限影響が詰められておらず、「REST API 化すれば作れる」という前提だけで起票されていた。権限制約を踏まえると実現手段が方針に反するため、機能自体を見送る。
