## 概要

ftgmail で `/ccskill-gmail` スキルを使ったセッションで、AI がアクティブアカウントを確認しようとして **`.ccskill-gmail/api info` を実行し `Unknown subcommand: info` エラー**を出した。

原因は SKILL.md 内に **名前が酷似した 2 つの CLI** が区別の説明なく登場することにある:

| CLI | 例 | 役割 |
|---|---|---|
| 管理用ラッパー `ccskill-gmail` | `ccskill-gmail info` / `history` / `status` / `setup` | インストール・環境・アカウント確認 |
| API 用 `.ccskill-gmail/api` | `.ccskill-gmail/api get action=...` | Gmail 操作（検索・閲覧・下書き・保存） |

`ccskill-gmail`（管理CLI）と `.ccskill-gmail/api`（API CLI）は **文字列として一方が他方の部分文字列**であり、極めて紛らわしい。SKILL.md は Overview で `ccskill-gmail info` を案内し、直後の Quick Start で `.ccskill-gmail/api` の説明に切り替わるが、**「この 2 つは別物」という明示がない**。結果、LLM は `ccskill-gmail info`（管理CLI の正規コマンド）を `.ccskill-gmail/api info`（API CLI のサブコマンド）と取り違える。

加えて Quick Start に「サブコマンドは 2 つ」と書かれているが後段では「5 つ」と書かれており**自己矛盾**しているため、LLM が CLI の仕様を誤認する。

#117 / #118 で繰り返し確認された **「SKILL.md の記述が LLM を誤誘導する」** 系列の問題。

## 出典

2026-05-29、ftgmail での `/ccskill-gmail` セッション。

1. アカウント確認のため AI が `.ccskill-gmail/api info` を実行 → `{"ok":false,"error":"Unknown subcommand: info. Use: get, post, download, save-html, save-pdf"}`
2. AI は当初「`info` サブコマンドは存在しない」と誤って結論づけた
3. 実際には `ccskill-gmail info`（管理CLI）が正規コマンドとして存在し、ftgmail でも正常動作することをユーザー指摘後に確認:
   ```
   Account:       oishi@feedtailor.jp
   Directory:     ~/projects/ftgmail
   Permissions:   Denied: move_to_trash
   Inbox:         7486 unread
   ```
4. ユーザーから「api には info サブコマンドはなく get/post 中心で、それぞれ action で指定する仕様。それがスキルに正しく書かれているか」と指摘を受けた

## 詳細（確認済みの事実）

### 問題1: 2 つの CLI が区別なく登場し、取り違えを誘発

- **SKILL.md L13**: `run `ccskill-gmail info` to confirm which account is active.`
- **SKILL.ja.md L15**: `` `ccskill-gmail info` でアクティブなアカウントを確認できます。``
- **SKILL.md L19**: `The skill is invoked through a single CLI: `.ccskill-gmail/api`.`

→ L13 で `ccskill-gmail`（管理CLI）を、L19 で `.ccskill-gmail/api`（API CLI）を、いずれも「アカウント確認 / このスキルの CLI」という近い文脈で提示するが、両者が別コマンドだという説明がない。`ccskill-gmail` というラッパー CLI の存在自体が SKILL.md 本文でほぼ説明されておらず（`ccskill-gmail history` 等は reference に散在）、LLM は `.ccskill-gmail/api` の方に引きつけて `.ccskill-gmail/api info` を組み立ててしまう。

`ccskill-gmail`（管理CLI）の実体は `commands/info.sh` 等を呼ぶラッパーで、サブコマンドは `setup / install / uninstall / update / update-all / apply-config / register / info / status / history / doctor / release / help / version`（`ccskill-gmail` スクリプト本体で確認）。`.ccskill-gmail/api` のサブコマンド（`get / post / download / save-html / save-pdf`）とは完全に別系統。

### 問題2: Quick Start の「2 つ」が後段の「5 つ」と矛盾

- **SKILL.md L19**: `It has two subcommands.`
- **SKILL.md L38**: `The subcommands are exactly five: `get`, `post`, `download`, `save-html`, `save-pdf`. Everything else ... is an `action` value passed to `get` or `post`.`

→ L19 を読んだ LLM は「get と post の 2 つだけ」と誤認する。実際は 5 つ（読み書きの本体は get/post、ファイル保存は download/save-html/save-pdf）。L38 の正しい記述と矛盾しており、Quick Start が誤った先入観を植え付ける。

### 問題3: get_profile action が reference/index.md に未記載

- アカウント確認は管理CLI `ccskill-gmail info` のほか、API CLI でも `.ccskill-gmail/api get action=get_profile` で取得できる（ftgmail で動作確認済み、`{"email":"oishi@feedtailor.jp","inboxUnreadCount":7486,"starredUnreadCount":10}` を返す）。
- しかし `reference/index.md` の Read Operations 表に `get_profile` の記載がない（`search` / `get_thread` / `get_message` / `list_labels` / `get_unread_count` のみ）。
- 管理CLI が使えない / api しか叩けない文脈では、LLM がアカウント確認手段を発見できず、存在しないサブコマンドを推測する余地が残る。

## 修正方針（案）

### 必須

1. **SKILL.md / SKILL.ja.md の Quick Start を「5 つ」に統一**
   - L19 `It has two subcommands.` → 5 つである旨に修正（例: `It has five subcommands: read/write go through `get` / `post`; file output uses `download` / `save-html` / `save-pdf`.`）。L38 と表現を揃え、Quick Start 単体でも誤解しないようにする。

2. **2 つの CLI の区別を Quick Start 冒頭で明示**
   - 「`ccskill-gmail`（管理用: install/info/status/history 等）」と「`.ccskill-gmail/api`（Gmail 操作用: get/post/...）」は**別物**であることを 1〜2 行で明記。
   - 特に「`info` / `status` / `history` は管理CLI `ccskill-gmail` のコマンドであり、`.ccskill-gmail/api` のサブコマンドではない（`.ccskill-gmail/api info` は無効）」と、取り違えやすい点を名指しで注意。

3. **reference/index.md に get_profile を追記**
   - Read Operations 表に `get_profile`（`.ccskill-gmail/api get action=get_profile` / アカウント・未読数を返す）を 1 行追加。reference/read.md に該当記述があるか確認し、なければ併せて追記。

### 検討

4. **アカウント確認の正規手段を 1 か所に集約**
   - 「アクティブアカウントの確認は `ccskill-gmail info`（推奨、権限や更新状況も表示）／ api だけなら `get action=get_profile`」と、用途別に並べて提示すると LLM が迷わない。

- 管理CLI `ccskill-gmail` のサブコマンド体系の変更
